# MarkdownEditor

[`MarkdownEditor`](/api/component/editor/classes/MarkdownEditor) is a **WYSIWYG rich-text editor whose public value is a Markdown string**, built on [Lexical](https://lexical.dev/). You edit a document as rendered rich text — no visible markup — and read or write it as Markdown through `getValue()` / `setValue()`. It is the editing counterpart to the read-only [`Markdown`](/components/Markdown) viewer.

Its dialect is deliberately the **exact subset the viewer renders** — headings, paragraphs, bold, italic, underline, inline code, coloured/sized/font-styled spans, ordered/unordered lists, blockquotes, fenced code, links, reference links, GFM pipe tables (with per-column alignment, widths, and merged cells), and `:::` block-alignment / explicit column-region fences. The editor reads Markdown with the viewer's own parser and writes it with its own serializer, so **a document saved by the editor renders in the viewer as the editor showed it**.

Lexical's editing view is a `contenteditable` element it owns and mutates directly — a *foreign live widget*, like the CodeMirror view behind [`CodeEditor`](/components/CodeEditor) — so the view mounts through the framework's DOM seam once the component is connected and sized. Unlike a code editor, Lexical keeps its editor **state** (a pure, DOM-free tree) separate from that view, so the Markdown value get/set/round-trip runs headless: offline the view never attaches, yet `getValue` / `setValue` and the command API still operate on the state.

## Usage

```typescript
import { MarkdownEditor } from '@jimka/typescript-ui/component/editor';
import { Fit } from '@jimka/typescript-ui/layout';

const host = new Panel({ layoutManager: new Fit() });
const editor = new MarkdownEditor('# Title\n\nSome **bold** text.');

host.addComponent(editor);
editor.on('change', ({ value }) => console.log(value)); // value is Markdown
```

`lexical` and the `@lexical/*` packages are runtime dependencies of the library, installed transitively when you install `@jimka/typescript-ui` — the same as `marked` for [`Markdown`](/components/Markdown). A consumer who never imports `@jimka/typescript-ui/component/editor` never bundles Lexical.

Give the editor a sized host (a `Fit` panel, as above, or an explicit `preferredSize`) — it fills its assigned box and scrolls internally, exactly like `CodeEditor`.

## Construction

`MarkdownEditor(value?, options?)` — the initial Markdown `value` is an optional positional argument (equivalent to the `value` option).

| Option | Type | Default | Purpose |
| --- | --- | --- | --- |
| `value` | `string` | `""` | Initial Markdown source. |
| `readOnly` | `boolean` | `false` | Whether the editor rejects edits. |
| `mode` | `"wysiwyg" \| "source"` | `"wysiwyg"` | Which editing surface is shown — see [Source / WYSIWYG mode](#source-wysiwyg-mode). |
| `listeners` | `{ change?: (payload) => void, selectionstate?: (payload) => void }` | — | Construction-time listener bag for the `"change"` and `"selectionstate"` events. |

Inherits the common [`ComponentOptions`](/api/core/interfaces/ComponentOptions) fields (preferred size, background, foreground, etc.).

## Supported constructs

The editor edits, and emits, only the constructs the [`Markdown`](/components/Markdown) viewer renders. The table gives the standard form an edited block is written in; a block left unedited saves as it was written (see [Common methods](#common-methods)):

| Construct | Markdown emitted |
| --- | --- |
| Heading | `# ` … `###### ` |
| Paragraph | plain text |
| Bold | `**bold**` |
| Italic | `*italic*` |
| Inline code | `` `code` `` |
| Unordered list | `- ` (an authored `*` or `+` is kept) |
| Ordered list | `1. ` (an authored `1)` is kept) |
| Blockquote | `> ` |
| Fenced code | ` ``` ` fence; `~~~` when its info string holds a backtick; a loaded info string keeps the words after its language |
| Strikethrough | `~~struck~~` |
| Underline | `++underlined++` |
| Coloured / sized / font-styled span | `[text]{color=... font=... size=...}`; a loaded span keeps its attributes' order and any it does not style with |
| Link | `[text](url)` |
| Reference link | `[text][label]`, `[label][]`, `[label]` as written — see [Reference links](#reference-links) |
| Table | pipe rows plus a `\| --- \|` delimiter row |
| Table column width | delimiter cell's trailing `{width=240}` |
| Merged table cell | body cell's `<<` (from the left) / `^^` (from above) |
| Block alignment / column region | `::: {align=... gap=...}` … `:::`, columns split by `\|\|\|` |
| Sized image | `![alt](src){width=... height=...}`; a loaded image keeps its attribute group as written while its size is unchanged |
| Underscore emphasis | read; written as `*` / `**`, or as `_` / `__` around emphasis whose own `*` the viewer would pair with it |
| Setext heading | read; written `#`, or still setext (`===` / `---`) when its content spans lines and no line of it would read as a code fence or HTML block |
| Indented or `~~~` code | read; written as a fenced code block |
| Autolink | `<https://…>`; a bare URL, `www.` address or email address loaded from the document stays bare |
| Hard line break | `\` + newline (Shift+Enter, except where Markdown has no break — see [What Markdown cannot hold](#what-markdown-cannot-hold)); an imported two-space break keeps its spaces |

Images, sized via the same `{width=… height=…}` grammar as a table column width, **are** part of the dialect, authored through `insertImage` or the empty-line context menu's **Image…** item. A column's alignment (from the delimiter row's `:---` / `:---:` / `---:` markers), its width, and merged cells are all **preserved** across a load/edit/save round-trip and all authorable in the WYSIWYG surface, through `setTableColumnAlignment` / `setTableColumnWidth` / `mergeTableCells` / `unmergeTableCell` and the table-cell context menu's Align column/Column width…/Merge cells/Unmerge cell items.

### Reference links

A reference link — `[text][label]`, `[label][]` or `[label]` — is a link in the WYSIWYG surface, edited like any other, and is saved in the form it was written **while the label's definition in the saved document gives the link's URL and title**, matching labels as the viewer does (case and runs of whitespace aside, the first definition of a label winning). Once the link's text is edited or formatted, a `[label]` or `[label][]` reference is saved as `[text][label]`. Once the link's URL is changed (**Edit link…**), or its definition is edited, removed, or no longer the first for its label, the link is saved inline as `[text](url "title")` with its own URL — so **a save never changes where a link points**. A `[label]` reference is written `[label][]` where the character after it would otherwise join it to another construct (a `(`, `{` or `[`, or a `:` at the start of a block), and where it opens a list item's text as `[ ]`, `[x]` or `[X]`, which would read as a task checkbox. A link whose title holds a blank line, which no inline link can write, keeps its reference form while its definition gives its URL, and takes the definition's title. A definition counts wherever the viewer reads one — in a list item or a `:::` column too, also right after an HTML block left open there, which ends with its item or column — and the first definition of a label in the document is the one that counts.

Definition lines (`[label]: url "title"`) show as raw Markdown blocks (see below) and are saved exactly as written; a run of definitions on consecutive lines is one block, and a blank line ends the run, also when it is typed into one.

Editing the definitions changes what the editor shows only where the viewer would show something else. Text never becomes a link: a `[label]` you type, inside a link's text or not, is saved escaped, so a definition added for it later leaves it text. A reference link keeps its own URL, as above. A reference kept as written — one with empty text (`[][label]`), a reference image (`![alt][label]`, which shows its alt text), a reference inside a construct kept as source — shows what its definition gives it, so when a definition it uses is typed, edited, pasted or removed, its block shows what a save and a reload would show: the reference whose label no longer resolves shows as its text, and from then on is text.

### Kept as source

Markdown the editor has no rich-text form for is kept as source and saved exactly as written. Thematic breaks, HTML blocks and link reference definitions load as a **raw Markdown block** — shown in a monospace font, editable as text, saved exactly as written (once edited, without an empty first or last line and without the up to three spaces of indentation before it, which mean nothing to Markdown and would move it into a list above it; they stay where a line of the block is read by them, as the lines of a raw list's first item are) — and so does a blockquote holding more than one paragraph or another block, a whole list when it is tight — no blank line between its items or between an item's blocks — and an item holds a block right under another (`- a` over an indented `> q`; a nested list right under its item's text is no such block), or when an item holds Markdown the editor keeps as a raw block that would not read the same wherever it stands in the item — a quote that ends on a line without `>`, indented no deeper than the quote, that starts an HTML block (`> q` over `<div`: the viewer reads that line as part of the quote or as a block after it, depending on what follows the item), or text that only reads as it does with spaces before its first line, and a table whose body row holds more cells than its header (cells the viewer drops). Inline HTML, task-list markers, images the viewer will not render (which show nothing, as in the viewer), and links a link node cannot hold — one with empty text (`[](url)`), or whose whole text is another link (`[<https://a.test>](/b)`, which shows the inner link's text linked and formatted as the viewer shows it) — load as **atomic runs** that show what the viewer shows and save unchanged (a task-list marker an edit leaves alone on its item's first line, where it is no marker, saves as the text it shows, `\[x\]`); a soft line break inside a paragraph is one too, showing as a space and saving as the line break it was. The format toggles, text styles and links decline over a selection holding an atomic run other than a soft break (its source would not save the format the way it shows, and markers around it can change what it is — a task-list marker inside `**` is no longer one), and the link commands decline inside a link shown this way. No block stays inside a block that holds text only — a paragraph, a heading, a quote, a code block or a raw block. Joining a list item to the block before it (Delete at that block's end, a range deleted from that block into the item; Backspace at the start of a list's first item turns the item into a paragraph first) joins the item's text to it, and the blocks the item held follow it as blocks of their own, in order. A raw block and a code block hold only text: inside one, Enter adds a line (at a raw block's end it starts a new paragraph after it, at its start one before it; pressed over a selection with an end in a raw block, it removes the selection as Delete does and then does what it does at the caret that leaves, whichever way the selection was made), pasted content goes in as plain text (each block an item of a pasted list holds apart from the item's text, as two items are), Backspace at the start of a paragraph after the block (or Delete at the block's end) joins that paragraph to it as its Markdown, and so does the rest of a block a deleted range reaches into from inside it; the typing shortcuts do not apply there, and the format toggles, text styles, links, images and tables decline, since the block saves its text as written. Converting a block to a code block keeps its formatting, links and images as their Markdown in the code. A raw block keeps the indentation `marked` reads its lines by when removing it would change what the block is. That holds for each of its lines: a quote whose last line stays in it only while indented (`> q` over an indented `<div`) keeps that line's indentation, in the document, in a `:::` column and in a list item. An HTML block its own text does not close (`<!--` without `-->`, `<pre>` without `</pre>`) takes in everything after it in Markdown, so while blocks follow it in the editor — in a list item, also the item's nested lists — it saves as a paragraph of the same text — its first `<` escaped, its lines kept by line breaks — and the blocks after it stay their own; the editor then shows it as that paragraph, the moment an edit leaves its text open with a block after it, or a block is added after it. A raw block in a `:::` column — one of its blocks, or a block of a list item there — whose text holds a line the fence would read — a `:::` line, a `::: …` opener, a code fence it leaves open, or a `\|||` line — saves as a paragraph of the same text for the same reason, and the editor shows it as that paragraph: this is what an HTML block holding `:::` becomes when `setBlockAlignment` or `setColumnCount` wraps it, or when it is pasted or typed into a column. Likewise a paragraph loaded from a `::: …` line whose fence had no closing line — the fence then reads as ordinary text — is saved with that line escaped (`\::: …`) once a block after it holds a `:::` line that would close the fence. Enter or a line break with the caret inside an atomic run lands after it; typing there replaces the whole run, and Backspace deletes it whole. When a raw block's text is edited until it reads as more than one block — a blank line typed into an HTML block, a fence pasted into a thematic break's text — or as one block the editor holds as rich text — a tag a deletion broke, leaving a paragraph; the halves of a link reference definition a paste split, each now a paragraph of text — the editor shows it as the blocks it saves as, with the caret where it was in the text.

An inline construct the editor's own way of writing would read back differently — strikethrough over a space before a linked image, a bare URL in a heading whose id it is part of, a styled span with an attribute the editor drops — loads as atomic runs that keep its source: only the construct is kept, the text around it stays ordinary text, and the construct saves exactly as written. Clearing formatting over it keeps the formats its source writes. An edit that takes such a construct apart turns what is left of it into ordinary text, shown and saved as that text.

### What Markdown cannot hold

Some states a rich-text editor can make have no Markdown form: a save would write them differently from how they look. The editor does not make them, so what it shows is always what it saves.

- **Line breaks.** Markdown has no hard break at the end of a block, in a block holding nothing else, or in a level 3–6 heading (an ATX heading is one line; levels 1 and 2 save multi-line as setext). Shift+Enter does nothing there; a break another edit leaves at a block's end is removed, and one in a level 3–6 heading — a pasted `<br>`, a code block's lines when it becomes a heading — shows as the space it saves as, and so does one in a level 1 or 2 heading when a line of its setext form would read as a code fence or HTML block, which saves it on one line. A table cell keeps every break: its cell break shows anywhere.
- **Bold, italic and strikethrough at a run's edge.** Their delimiters cannot stand against whitespace inside them, nor against punctuation inside them with a letter outside (`x**(a)**b` reads as literal asterisks). Applying one of them trims the selection's edge spaces off it and does nothing on whitespace alone, and a selection reads as having it — on the toolbar, in the context menu and to the next toggle — when everything in it but the whitespace the format would be trimmed off carries it, so a second press over the same selection takes it off again; taking one off part of a run leaves the spaces around it plain. A format whose result still could not be saved as shown — emphasis or strikethrough opening with punctuation right after a letter or closing with it right before one — is declined, from a toggle, the keyboard shortcut or a typing shortcut alike (`x**(a)**` typed stays text). After a paste, a deletion, a cut, a split or typing, the formats are taken off such whitespace and punctuation instead: a space typed after bold text shows plain until the next word joins the run, and a word typed right before emphasis that opens with punctuation takes that emphasis off its edge.
- **Underline over `+`, a colour, font or size over `[` or `]`.** Underline's grammar cannot hold a `+`, nor a styled span's a bracket. The toggle or setter that would make one is declined; a `+` typed or pasted into underlined text, or a bracket into styled text, shows without the underline or style, as the save writes it.
- **An image whose alt text holds a bracket.** `insertImage` does nothing.
- **A link holding only a soft line break** at a block's edge, where the save drops it, is unwrapped.
- **Lists.** A change of bullet character or ordered delimiter starts a new list (`- a` then `+ b` are two lists), and the editor keeps such lists apart; lists of one marker made next to each other in the editor join, as Lexical joins them, and two a document loads apart (after an empty item) stay apart. Two raw list blocks an edit brings together, which the viewer would read as one list, are saved with a `[//]: #` line between them, a link reference definition that shows nothing; so are two inside one list item. A raw block an edit emptied counts as nothing between a list and a raw list. A list's looseness follows what its save reads as: a list left with one item of one block is tight, and a list whose item holds a block after its nested list is loose. A nested list follows its item's text directly and any other block of the item — a table, which would read its lines as rows, or a paragraph, which would take in an ordered list not starting at 1 — after a blank line, which makes the list loose; two nested lists of one item, or a nested list and a raw list next to it, that the viewer would read as one are saved with another bullet or delimiter. A list item holds blocks as the viewer shows them: further paragraphs, headings, code blocks, quotes, tables, `:::` fences and raw Markdown blocks (a link reference definition among them, also one repeating an earlier label, which Markdown ignores) load as blocks of the item, before or after its nested lists; a run of definitions on consecutive lines is one block there too, and a blank line between two definitions makes them two. A nested list that itself loads as a raw Markdown block is such a block of its item, and the list around it loads by the same rule as any list. A raw Markdown block in a list item follows one rule: its text, saved from its first line that holds something to its last and without the spaces before it that mean nothing to Markdown, must read in the item exactly as it reads on its own, wherever it stands there. A list loads with such a block only when that holds, and when an edit leaves raw text for which it does not — spaces typed before a raw list whose lines are measured by them — the editor reads the whole list again as its save reads, so it shows what loading that save shows (the list may then show as a raw block). Pasting several blocks into a nested list item, or **Insert line after block** inside a nested list, adds such a block to the outer item, and it is kept through a save and a load. A list that is copied and pasted keeps the paragraphs its items hold, and a format the editor declines on an item's text leaves them as they were. An edit of an item's own text leaves the blocks the item holds as blocks: Enter in that text moves what follows the caret into the new item, the item's blocks with it; text typed or pasted over all of that text replaces it and nothing else; and once an item's own text is deleted, the paragraph after it is its text, as Markdown reads an item whose first line is empty; before any other block — a nested list, a heading, a table — the empty text line stays, to type the item's text in, and Enter on that empty line takes the item out of its list, as Enter in an empty item does. A nested item moved out of its list — Backspace at its start, or a block type or the list toggle set on it — takes along the blocks the outer item holds after that list, which follow it as they did before. An item that is indented or moved out keeps its own nested list under it. Joining an item's text to the block before it — Delete at that block's end, or a range that ends in the text — joins the two texts, and what the item held after its text follows into the item before it; for a list's first item, the blocks up to its first nested list follow the text out of the list. Backspace at the start of an item's further paragraph joins it to the block before it. A block type set on such a further block changes it in place; set on the item's own text, it takes the item out of its lists. A list toggle on an item's own text, or on the heading an item opens with, takes the item out of its lists the same way, or makes it an item of the other kind there. Either way the blocks the item holds up to its first nested list go with the text — after the paragraph, or as the blocks of the new item — and the nested list and what follows it stay in the list, in an item with no text. A list toggle on a further block of an item makes that block an item of its own, with the blocks after it. With an end of the selection between two blocks rather than in a text — `deleteTable()` leaves the caret on a list, a list item, a `:::` block or one of its columns, or on the document itself — a list toggle and `setBlockType` act on blocks of text all the same. A caret there goes into the block of text after it, or the one before it when none follows; a table beside it is passed over, and a `:::` column the deleted table left empty gets an empty paragraph for it. In a document the deleted table left empty, and at a point code sets with a table on both sides, the command makes its block new and empty there. The ends of a range go inward: its start into the first block of text after it, its end into the last one before it, so the command changes the blocks between the two ends and never one outside them; a range with no block of text between its ends acts as a caret where it starts. A range that only covers a column a deleted table left empty leaves that column as it is and changes the blocks of text around it. `deleteTable()` on a table that stands next to another table leaves the caret on that other table, where these commands are unavailable, as they are for any caret on a table. A copy that reaches from an item's text into a later block of the same item — a further paragraph, a nested list — copies the item, holding both. Deleting everything a list item holds — a range from the start of its text to the end of its last block, or `deleteTable()` on a table that is all the item holds — leaves that item, empty, with the caret in it, as deleting the text of two plain items leaves an empty item; a list is never left without one. Backspace at the start of a block after a `:::` block, or after a list whose last item ends in a table or a `:::` block, does what it does after a table: a block that holds something stays where it is and nothing is joined, and an empty block is removed, the caret going to the end of the table's last cell or of the `:::` block's last block. A caret between the blocks of an item, where the arrow keys leave one beside a table, takes Enter, typed text, a paste and an inserted image in a paragraph of that item, and so does a range whose removal leaves the caret there; Shift+Enter changes nothing there, since there is no line to break. Blocks pasted into a block that a list item holds — one of its further paragraphs, a heading or a quote — become blocks of that item, the block split at the caret, as a paste at the top level splits a paragraph: the text after the caret joins the last pasted block when that is a block of text, and stays a paragraph of its own after a pasted list or table. A list pasted at an item's text leaves what the item holds with the text it followed, in the last pasted item. A paste at an item's text that ends in a table or a `:::` block — a pasted table, or a pasted list whose last item ends in one — leaves the text after the caret an item of its own after the pasted blocks, with the blocks its item held, as a table inserted at that caret does; with nothing after the caret, or blank text alone, no empty item is left. A raw thematic break of the bullet's own character that opens an item (`---` in a `-` list) is saved under the marker on a line of its own, since `- ---` is one thematic break.
- **Tables.** A table stays rectangular and aligned by column: a row an edit leaves short is filled with empty cells, a merged cell spans no row past the table's end, a header cell an edit leaves merged (a range deleted from the header row into a merged body row) is split into the cells it covered, since Markdown merges body cells only, every body cell takes its column's alignment (the header cell's, which the delimiter row writes), and a heading, quote, code block or list pasted into a cell becomes the lines of text the cell saves — for a list, each item's text and each block an item holds on a line of its own. Table rows or cells pasted without their table (a range selection set by code that stays inside one table copies them that way; a selection of cells made with the mouse or the keys copies a table) paste as a table holding them does, a short row filled with empty cells: as a new table, or, in a cell of another table, over that table's cells from that cell on. A selection that runs from outside a table into one of its cells covers the whole table, as the editor highlights it: deleting, cutting, typing or pasting over it removes the selected text outside the table and the whole table, and leaves the block on the table's far side as it was (two lists of one marker the table stood between then join, as lists made next to each other do). A cut or a copy of such a selection — from the keyboard, the context menu, `cut()` or `copy()` — puts on the clipboard what the cut removes, the whole table included; a copy leaves the document and the selection as they are, and a selection that crosses no table's edge (inside one cell, over cells of one table, or outside every table) is copied as it stands. `insertTable` and `insertImage` remove such a selection the same way before they insert (the removal and the insertion are one undo step), and where that leaves the caret at a block that cannot take what is inserted — a raw Markdown block or a code block, and for a table another table — the table or image goes into a new paragraph where the removed table was. An edit that changes nothing leaves the selection as it was, as it leaves any other: a paste that inserts nothing (a pasted screenshot, an empty clipboard), and Shift+Enter where the removal would leave the caret with nothing after it in its block (see *Line breaks* above).
- **Columns.** A `:::` column exists only inside its fence. Columns pasted anywhere else — a selection copied across two columns and pasted into a paragraph, another column or a table cell — become the blocks they hold, which is what the save writes, and paste as those blocks would: a block of text (a paragraph, heading, quote, code block or raw Markdown block) that comes first joins the block at the caret, and one that comes last takes in the rest of that block.
- **Empty links.** A link a paste leaves with no text at all is removed: it shows nothing and the save writes nothing for it.
- **Anything else.** `marked` has corners no writing reaches — a code span holding a backtick, or a `<` with a `>` later in the block, hides the emphasis delimiters after it — so text a paste, a deletion or typing leaves where no writing of it reads back as shown shows as its save reads, as a reload of the document would show it.

## Formatting

There is no built-in toolbar in v1. Formatting is invoked four ways, all provided by Lexical (the right-click menu is this component's own addition):

- **Markdown-shortcut typing** — `# ` → heading, `**b**` → bold, `- ` → bullet, `1. ` → numbered, `> ` → quote, ` ``` ` → code block, auto-applied as you type.
- **Keyboard shortcuts** — `Ctrl/Cmd+B` (bold), `Ctrl/Cmd+I` (italic), `Ctrl/Cmd+Z` / `+Y` (undo/redo).
- **Command API** — thin imperative methods you can wire to your own [`Button`](/components/Button)s to build a toolbar.
- **Right-click context menu** — a self-wired menu on the WYSIWYG surface whose contents depend on what was clicked: a word or selection gets inline-format and block-style commands, plus an **Alignment** submenu (Left/Center/Right/Justify/Default) applying `setBlockAlignment` and a **Columns** submenu (fixed 2/3/4-column presets and None) applying `setColumnCount` — so the column count can be changed from inside a populated column, not just from an empty line; an empty line gets a **Heading** submenu (h1–h6), an **Insert** submenu bundling **Quote**, **Code block**, **Bulleted list**, **Numbered list**, **Table** (a 2×3 starter table), and an **Image…** item prompting for a source URL and applying it through `insertImage`, and the same **Columns** submenu; a table cell gets the same inline-format commands (no block style — a cell holds inline text only) plus a **Table** submenu bundling an **Insert** submenu (row above/below, column left/right), a **Delete** submenu (row, column, or the whole table), **Merge cells** (over a drag-selected range of cells), **Unmerge cell**, **Column width…** (prompts for a pixel width via a dialog, applying it through `setTableColumnWidth`), and an **Align column** submenu offering Left, Center, Right, and None — the four alignments a GFM delimiter row can express — with a checkmark on the column's current choice; alignment is a whole-column property, so choosing one re-aligns every cell of that column, header included, not just the clicked cell. The inline-format toggles are **Bold**, **Italic**, **Underline**, **Strikethrough**, and **Code**, and a word/selection or a table cell also gets a **Text style** submenu with **Colour** / **Font** / **Size** sub-submenus, each a fixed preset list plus a **Default** item that clears the override. A word/selection or a table cell also offers **Insert link…** (dimmed unless there is a selection or expandable word to wrap) when the click is not inside a link, or **Edit link…** / **Remove link** when it is — Insert/Edit prompt for a URL via a dialog, applying it through `toggleLink`; Remove unwraps the whole link via `removeLink()` regardless of how much of it is selected. Clicking inside a blockquote, a list, a fenced code block, or a table cell additionally shows **Insert line before block** / **Insert line after block**, which add an empty paragraph immediately outside the whole enclosing block (for a list, outside the entire list, not just the clicked item; for a table cell, outside the whole enclosing table, not just the clicked cell) and move the caret into it; a plain paragraph or a heading never show these two items. Every context leads with **Cut / Copy / Paste**; Cut and Copy are dimmed unless there is text to act on — a real selection, or (a collapsed caret) the enclosing word a format toggle, Cut, or Copy would expand into — and Paste is always enabled. Right-clicking never selects anything on its own: a collapsed caret inside a word stays a plain blinking caret while the menu is open. Choosing a format toggle, Cut, or Copy is what expands it to the whole word (visibly selecting it, so a follow-up action in the same still-open menu sees the same wider selection); Paste always acts on whatever is currently selected, so pasting right after opening the menu — before anything else — lands at the original caret, splitting the word rather than replacing it, while pasting after a format toggle (or Cut/Copy) replaces the word that toggle just selected. No consumer wiring needed — right-clicking the surface shows it directly. Shift+F10 or the ContextMenu key opens the same menu for wherever the caret or selection is, positioned there. A right-click that moves the caret (on Linux and macOS the browser moves it before the menu opens) gets the menu for the caret's new place: its checkmarks, its Cut/Copy state and its dimmed items all describe what the items will act on. While table cells are selected a right-click leaves that selection in place, wherever it lands, and the items go on acting on the cells, so the menu is the table-cell one even for a click outside the table. An item whose command would do nothing at the selection is dimmed: the format toggles, Text style and Insert/Edit link in a raw Markdown block, a code block or over text kept as Markdown source; the format toggles and Text style also for a selection that holds no text (from the end of one line to the start of the next, or over an image alone), and Insert link… where there is nothing a link could hold; the Insert submenu's Table and Image… when the selection touches a raw Markdown block or a code block, and Table also when the selection lies inside a table; Text style inside a link; Edit link… and Remove link in a link nested in a link; Block style, Heading and the list and block conversions when the selection reaches into a table cell; **Clear formatting** where the selected text carries no format; and the two **Insert line** items when the selection is anchored outside the block that was clicked. While table cells are selected the format toggles apply to the cells that can take them, and everything else that needs a text selection is dimmed — Text style, the link items, Clear formatting, the Insert line items, and in the **Table** submenu every entry but **Merge cells**, which in turn is dimmed unless more than one cell is selected; **Unmerge cell** is dimmed outside a merged cell. With no selection at all every item that acts on one is dimmed, **Alignment** and **Columns** included. Paste is the one item this does not cover: it stays enabled though it needs a text selection. In a read-only editor the menu offers only Copy.

### Command API

| Method | Effect on the current selection |
| --- | --- |
| `toggleBold()` / `toggleItalic()` / `toggleInlineCode()` / `toggleStrikethrough()` / `toggleUnderline()` | Toggle the inline format. |
| `setTextColor(color)` / `setFontFamily(family)` / `setFontSize(size)` | Set (or, with `null`, clear) the selection's text colour / font family / font size. No-op inside a link, in either mode. |
| `clearFormatting()` | Clear every inline text format (bold, italic, strikethrough, underline, inline code, …), leaving plain text. Does not clear a colour/font/size override — use the matching setter with `null` for that. Block type is untouched. |
| `toggleUnorderedList()` / `toggleOrderedList()` | Convert the selected blocks into a bulleted / numbered list, or out of one. When every selected block is the text (or the heading) an item of a list of that kind opens with, those items leave the list: each becomes a paragraph, the blocks its item holds up to its first nested list follow it, and the list is split around them. Otherwise each other selected block becomes an item of such a list at the top level (or in its `:::` column): an item of a list of the other kind changes alone, its list split around it, and keeps the blocks it holds up to its first nested list — select a whole list to convert it whole — and a new item joins a list of that kind right before or after it — the joined list is tight when the lists it joins are tight and the new item holds its text alone, and loose when one of them is loose or the item holds further blocks. A block a list item holds after its text becomes an item of its own, with the blocks after it. A task item's `[ ]` / `[x]` marker stays a marker while its item stays an item, and becomes the text it shows when the item's text leaves its list. |
| `toggleLink(url)` | Wrap the selection in a link to `url` (a collapsed caret first expands to its enclosing word), or unwrap it when `url` is `null`. Updates the URL in place, rather than double-wrapping, when the selection already sits inside one existing link. |
| `removeLink()` | Remove the link enclosing the current selection, unwrapping it back to plain text — the whole link, regardless of how much of it (if any) is selected. |
| `setBlockType(type)` | Convert the selected blocks to `"paragraph"`, `"h1"`–`"h6"`, `"quote"`, or `"code"`. A list item's text is taken out of its lists, and the blocks the item holds up to its first nested list follow it. A task item's marker stays as the text it shows, and in a code block as it was written. |
| `insertTable(rows, columns)` | Insert a table at the caret; the first row is the header row. Without a text selection it goes in at the document's end. No-op where it would land inside another table: with the selection inside one, or, without a text selection, with the document ending in one. A selection that runs from outside a table into one of its cells is removed first, that table included, and the new table goes in where it started. |
| `insertParagraphBeforeBlock()` / `insertParagraphAfterBlock()` | Insert an empty paragraph immediately before/after the blockquote, list, fenced code block, or table enclosing the caret, and move the caret into it. For a list or a table cell, this is the whole list or table, not just the caret's item or cell. |
| `insertTableRow(after?)` / `deleteTableRow()` | Insert a row after (default) or before the current row, or delete it. |
| `insertTableColumn(after?)` / `deleteTableColumn()` | Insert a column after (default) or before the current column, or delete it. |
| `setTableColumnAlignment(alignment)` | Set the alignment (`"left"` / `"center"` / `"right"` / `"none"`) of the column holding the caret, on every cell in that column. |
| `deleteTable()` | Delete the entire table containing the caret, including every row and cell. |
| `mergeTableCells()` | Merge the cells of the current drag-selected range into one. No-op unless the selection spans more than one cell. |
| `unmergeTableCell()` | Split the merged cell containing the caret back into its individual cells. |
| `setTableColumnWidth(width)` | Set (or, with `null`, clear) the width in pixels of the column the caret sits in. |
| `setBlockAlignment(align)` | Set (or, with `null`, clear) the block alignment of the top-level blocks the selection spans, wrapping (or unwrapping) a `:::` fence as needed. |
| `setColumnCount(count, gap?)` | Grow or shrink the number of explicit column regions in the block the selection sits in (or wrap the top-level blocks the selection spans in a new one), and optionally set the column gap. Growing appends empty columns; shrinking merges the surplus columns' content into the last column kept, except a column left exactly as this method created it (a single empty paragraph), which is dropped instead. `count` is clamped to 1–6; `null` means one column. Unwraps the fence when the result carries no alignment and no more than one column. |
| `insertImage(src, options?)` | Insert a sized, validated image at the caret. `options` may set `alt`, `width`, and `height`. Without a text selection it goes in at the document's end. No-op when `src` fails the scheme allow-list, or `alt` holds a `[` or `]`. |
| `cut()` / `copy()` | Write the selected text to the system clipboard; `cut()` also removes it. A selection that runs from outside a table into one of its cells is cut or copied with the whole table (see *Tables* above). `cut()` is refused while the editor is [read-only](#read-only): nothing is copied or removed. |
| `paste()` | Read the system clipboard and insert it at the caret, replacing any selection. Async: resolves `true` when the clipboard was read, `false` when the browser would not allow the read. Refused while the editor is [read-only](#read-only): it resolves `false` without reading the clipboard. |

Each command operates on the current selection and no-ops (without throwing) when there is no selection, except `insertTable` and `insertImage`, which then insert at the document's end. The format toggles, the colour/font/size setters and `toggleLink` also no-op when their result could not be saved as it shows — see [What Markdown cannot hold](#what-markdown-cannot-hold). The format toggles, the colour/font/size setters, `toggleLink`, `insertTable` and `insertImage` also no-op when the selection touches a raw Markdown block or a code block (for the two inserts without a text selection: when the document ends in one), and the toggles, setters and `toggleLink` when it holds an atomic run kept as source (see [Kept as source](#kept-as-source)). With whole table cells selected, a format toggle works cell by cell under the same rules: a cell holding such a run, or whose result could not be saved as it shows, is left as it is, as is a cell with no text (an empty one, or one holding an image alone), and the rest take the format, which comes off when all the text in the cells taking it already has it. `setBlockType` and the two list toggles no-op when the selection touches a table cell — whole cells selected included — which holds text only — a heading or list made there would be saved into the cell as its literal syntax. A list next to a raw list block is saved with another bullet or delimiter when its own would make the viewer join the two lists. The row/column/table commands additionally no-op when the caret is not inside a table cell, and for a selection that starts in a cell and runs out of its table; `mergeTableCells` needs more than one cell selected instead. `insertParagraphBeforeBlock`/`insertParagraphAfterBlock` no-op when the caret is not inside a blockquote, list, fenced code block, or table cell. A command declined for any of these reasons changes nothing: the document, its selection and the undo history stay as they were, and neither `"change"` nor `"selectionstate"` fires. The one exception is a format, style or link declined because its result could not be saved as it shows: that is found by trying it, so a collapsed caret is left expanded to its word.

`paste()` depends on the browser granting a clipboard-read permission, which some browsers prompt for and some refuse outright for page scripts; a refused or unavailable read resolves `false` rather than throwing. The context menu's own Paste item shows a toast asking the user to press Ctrl/Cmd+V instead when this happens — `paste()` itself stays silent, so a consumer wiring their own Paste button can show their own message.

In `"source"` mode, the following edit the raw Markdown directly instead of the Lexical document: the five format toggles, `toggleLink`/`removeLink`, `clearFormatting`, `cut`/`copy`/`paste`, `setBlockType`, `toggleUnorderedList`/`toggleOrderedList`, `insertParagraphBeforeBlock`/`insertParagraphAfterBlock`, `insertImage`, `insertTable`, and `setTextColor`/`setFontFamily`/`setFontSize`. The other eleven — `setBlockAlignment`, `setColumnCount`, and the nine table-structure commands (`insertTableRow`/`deleteTableRow`, `insertTableColumn`/`deleteTableColumn`, `setTableColumnAlignment`, `deleteTable`, `mergeTableCells`, `unmergeTableCell`, `setTableColumnWidth`) — stay WYSIWYG-only and no-op in `"source"` mode.

## Live selection state

`getSelectionState()` returns a snapshot of what the caret currently sits
in — the five inline-format flags (`bold`/`italic`/`strikethrough`/`code`/`underline`),
whether there's a selection to act on, the URL of an enclosing link (if any),
which commands would apply there (the eleven `can…` fields),
whether it's inside a table cell and that column's alignment, and the
enclosing `:::` block's alignment and column count — and `on('selectionstate', fn)`
fires whenever that snapshot changes, for building a toolbar whose buttons
press, enable, or check themselves to match the caret's position (as
[`MarkdownDocumentPanel`](/components/MarkdownDocumentPanel)'s own toolbar
does):

```typescript
editor.on('selectionstate', (state) => {
    boldButton.setSelected(state.bold);
    tableButton.setEnabled(state.canEditTable || state.canMergeCells || state.canUnmergeCell);
});
```

The event does not fire for the editor's initial position, whichever
surface it starts on, so a toolbar seeds itself by calling
`getSelectionState()` once when it wires the listener; the one exception is
the build-time correction of the two insert fields described below. It fires on every editor commit whose resulting state differs
from the last one reported — including a same-position format toggle
(clicking a format button doesn't move the caret, but still changes what
it reports), not just a caret move. Outside a table, `tableColumnAlignment`
is `null`, as it is, with `inTable` `false`, while whole table cells are
selected and for a selection that starts in
a cell and runs out of its table; outside a `:::` block, `blockAlignment` is `null` and
`columnCount` is `1`. `inTable` says where a caret or a text selection is, not what
applies there: a control that runs a table command reads the three table
fields below.

Eleven fields report whether a group of commands would apply at the
selection, so a toolbar can grey out what would do nothing. Each command
declines on its own field before it touches anything, so a field that is
`false` means the command changes neither the document nor the selection:

| Field | Commands | `false` when |
|---|---|---|
| `canFormat` | the five format toggles | there is no selection; the selection touches a raw Markdown block or a code block; it holds text kept as Markdown source; it is not collapsed and holds no text (from the end of one block to the start of the next, or over an image alone); table cells are selected and none of them holds text free of such source |
| `canStyle` | `setTextColor` / `setFontFamily` / `setFontSize` | there is no selection; the selection touches a raw Markdown block or a code block, or holds text kept as Markdown source; it is not collapsed and holds no text; the caret is inside a link; table cells are selected |
| `canLink` | `toggleLink(url)` | there is no selection; the selection touches a raw Markdown block or a code block, or holds text kept as Markdown source; either end of it is in a link nested in another link; there is nothing a link could hold (a caret in an empty block, or a selection holding neither text nor an image); table cells are selected |
| `canRemoveLink` | `removeLink()` | the selection is not inside a link, or that link is nested in another link; there is no selection; table cells are selected |
| `canSetBlockType` | `setBlockType`, `toggleUnorderedList`, `toggleOrderedList` | there is no selection; table cells are selected; the selection reaches into a table cell, or stands on a table and holds no block of text |
| `canSetBlockLayout` | `setBlockAlignment`, `setColumnCount` | there is no selection; table cells are selected |
| `canInsertTable` | `insertTable` | the selection touches a raw Markdown block or a code block; it lies inside one table; without a text selection (none, or table cells selected), the document ends in a raw Markdown block, a code block or a table |
| `canInsertImage` | `insertImage` | the selection touches a raw Markdown block or a code block; without a text selection (none, or table cells selected), the document ends in one |
| `canEditTable` | `insertTableRow` / `deleteTableRow`, `insertTableColumn` / `deleteTableColumn`, `setTableColumnAlignment`, `setTableColumnWidth`, `deleteTable` | the caret is not in a table cell; table cells are selected; the selection starts in a cell and runs out of its table |
| `canMergeCells` | `mergeTableCells` | fewer than two table cells are selected |
| `canUnmergeCell` | `unmergeTableCell` | `canEditTable` is `false`; the caret's cell spans one row and one column |

`canInsertTable` is `true` for a selection that runs from outside a table
into one of its cells, whichever way it was made: `insertTable` removes that
selection first, its table included, so the new table does not land in a
cell. `canLink` is `true` at a caret anywhere in text, where `toggleLink`
links the whole run the caret is in, so it does not say whether a word is
selected: a Link control is enabled on
`canLink && (hasSelectedText || linkUrl !== null)`, or on `canRemoveLink`
for its Remove action, as `MarkdownDocumentPanel`'s is. A Table control is
enabled on `canEditTable || canMergeCells || canUnmergeCell`, so its Merge
cells entry is reached with cells selected, and dims each entry on its own
field. A caret takes a format or a style as pending, for the text typed
next, which is why `canFormat` and `canStyle` are `true` at a caret in an
empty block. The fields follow the rules a command declines on up front; a
format, style or link that turns out not to be writable as Markdown is still
declined when tried (see
[What Markdown cannot hold](#what-markdown-cannot-hold)). A field covers a
command, not a call. Where the argument asks for what is already there —
`setBlockType("paragraph")` in a paragraph, `setTableColumnAlignment` or
`setTableColumnWidth` with the value the column has, `setBlockAlignment` or
`setColumnCount` with what the `:::` block has, or with nothing to clear
outside one — the field is `true` and the call changes nothing, as a
declined one does: no block is replaced, no undo step is added and no event
fires.

Before the editor has a selection — a freshly built editor nobody has
clicked into — every field but the two inserts is `false`: those commands
act on a selection. The two inserts make a caret of their own
at the document's end, as they also do while table cells are selected, so
they follow how the document ends: `false` where the insert would land in a
block that declines it. Until the Lexical editor is built — on the WYSIWYG
surface's first layout, or by the first command — both report `true`, and
`"selectionstate"` fires once when the build finds either one `false`. In
`"source"` mode, where a command declines depends on the raw text around the
selection and is not predicted: the fields are `true`, except
`canRemoveLink`, which is `true` only inside a link, and
`canSetBlockLayout` and the three table fields, which are `false` because
the alignment, column and table commands are no-ops there. In a
[read-only](#read-only) editor all eleven are `false`, on either surface;
`inTable` still says where a caret or a text selection is.

In `"source"` mode the five format flags, `hasSelectedText`, and `linkUrl`
are derived from the raw Markdown around the caret, read with the viewer's
parser — a flag is set while the selection lies inside that format (a
`**…**` or `__…__` run for `bold`), and `linkUrl` is the target of a link of
any form around it; `inTable` is always
`false`, `tableColumnAlignment` and `blockAlignment` are always `null`, and
`columnCount` is always `1` — the fields a Lexical-only construct has no
raw-text equivalent for. `setMode` emits a fresh state for the surface it
switches to, once that surface is the one showing, so a toolbar never keeps
the outgoing surface's last-reported state after a switch. `setValue`
reports the state of the document it loads; the first one on an editor not
built yet does not report the document it replaces.

A source-mode format flag is set whenever a run of that format encloses the
selection, however far out it sits — `bar` in `**foo, **bar** az**` reports
`bold` — and pressing that format's toggle then removes it from the whole
selection, as in WYSIWYG mode: every run of it around the selection goes, and
a run covering more than the selection is split around it
(`**foo,** bar **az**`). When no Markdown the editor can write reads back
that way, the press changes nothing.

## Common methods

| Method | Purpose |
| --- | --- |
| `getValue()` / `setValue(value)` | Read or replace the whole document as a Markdown string. |
| `getMode()` / `setMode(mode)` | Read or switch the editing surface — see [Source / WYSIWYG mode](#source-wysiwyg-mode). |
| `getReadOnly()` / `setReadOnly(readOnly)` | Read or toggle whether the editor accepts edits. |
| `on('change', fn)` / `off('change', fn)` | Subscribe to content changes (the payload carries the new Markdown). |
| `getSelectionState()` | Read the caret's current tracked state — see [Live selection state](#live-selection-state). |
| `on('selectionstate', fn)` / `off('selectionstate', fn)` | Subscribe to changes in that state. |
| `dispose()` | Detach the Lexical registrations and the editor root — call before discarding a dynamically-built `MarkdownEditor`. |
| `markClean()` | Clear the dirty flag, accepting the current document as the clean baseline. |

Saving changes only what was edited. A top-level block you did not touch — a paragraph, list, table, quote or fence — is written back exactly as it was loaded, with the blank lines around it; an edited block is written in the editor's standard form (see [Supported constructs](#supported-constructs): `*` emphasis, `#` headings, fenced code, …). An unedited document, and a switch to source mode and back, return the text unchanged except that `\r\n` line endings become `\n`. Undo keeps this: undoing past a `setValue` or a switch back from source mode returns the earlier document's untouched blocks as written. An untouched block is also written in the standard form where its text would read differently in its new place: an indented block that now follows a list, an unclosed code fence that something now follows, a paragraph opening a `[` it does not close where text now written after it would close it into a link reference definition (`marked` reads a definition's label across blank lines), and — once a link reference definition is edited — a block whose bracketed text the new definitions read differently (text that becomes a link, or a link whose URL changes); every other block keeps its source.

## Source / WYSIWYG mode

The editor has two surfaces, selected by its `mode`:

- `"wysiwyg"` (default) — the Lexical rich-text surface described above.
- `"source"` — a raw-Markdown [`CodeEditor`](/components/CodeEditor), for editing the Markdown text directly.

Both surfaces are bound to the **same Markdown value**, so `getValue()` / `setValue()` and the `"change"` event behave identically whichever mode is active, and switching modes **preserves the document** (the text is converted across on each switch). `setReadOnly` applies to both surfaces. In `"source"` mode, HTML is typed literally — no close tags are added and Enter keeps the line's indentation; see [CodeEditor's built-in languages](/components/CodeEditor#built-in-languages).

```typescript
const editor = new MarkdownEditor('# Title', { mode: 'source' });

editor.getMode();            // "source"
editor.setMode('wysiwyg');   // convert the source text into rich text and show it
editor.getValue();           // same Markdown, regardless of the active mode
```

Like the [command API](#command-api), the mode toggle is **consumer-wired** — the editor ships no built-in chrome. Drive `setMode` from your own control (e.g. a [`ToggleButton`](/components/ToggleButton)) when you want to expose the switch to users.

Which [command API](#command-api) commands edit the raw Markdown directly in `"source"` mode, and which stay WYSIWYG-only and no-op there, is listed at the end of that section. Source mode reads the raw text with the viewer's own parser — the one the WYSIWYG surface loads with — so its commands see each construct as the viewer does: `__bold__` and `_italic_` as well as `**bold**` and `*italic*`, reference links (`[docs]`, `[docs][]`, `[docs][d]`), bare-URL, `www.` and email autolinks, link text holding brackets and destinations holding parentheses. Each command also checks its result before applying it: when the edited text would not read back as intended with nothing else changed — markers that Markdown's flanking rules leave literal (`**hello.**b`), a marker or bracket straight after an escaping backslash (`C:\Users`), a wrap that would re-pair other markers — it does nothing.

The five format toggles remove the format from the whole selection when a run of it encloses the selection, in any form the viewer reads (`toggleItalic()` on `_hello_` gives `hello`, `toggleBold()` on `bar` in `__foo, __bar__ az__` gives `__foo,__ bar __az__`), and otherwise write the dialect's own marker around the selection (`**`, `*`, `~~`, `++`, `` ` ``) — around a whole code span or autolink when the selection is its text. A selection reaching into a list marker, a quote's `>` or a heading's `#` acts on that block's text. They do nothing inside a code block, on a `:::` fence line or a table delimiter row, inside an autolink or image, inside a code span (but for `toggleInlineCode()`, which takes the selected code out of the span), for a selection cutting through another run's markers or a link's destination, and when no Markdown reads back as the selection without the format (a bold run cannot open between `9` and `[` in `zq0029**[r]**`). `toggleLink` re-points the link of any form around the selection — a reference link or an autolink becomes an inline link, a reference link keeping its title — and wraps a selection holding no link; `removeLink` unwraps any form, escaping an autolink's `:`, `.` or `@` (`https\://…`) so its text is not linked again, and takes a link nested in another link's text out of it (`[[a](/in) b](/out)` gives `a[ b](/out)`) so its text is unlinked rather than joining the outer link; `clearFormatting` removes every emphasis run and code span the selection touches.

The block commands — `setBlockType`, `toggleUnorderedList`/`toggleOrderedList`, `insertTable` and `insertParagraphBeforeBlock`/`insertParagraphAfterBlock` — act on whole blocks as the viewer reads them: the paragraphs (lazy continuation lines included), headings (a setext underline included), list item texts and code blocks the selection's lines touch, never part of one. A block they convert leaves the quotes and list items around it for the top level (or its `:::` column), where the WYSIWYG surface holds headings, quotes, lists and code blocks. Those containers split around it, and what followed it inside them stays there, re-opened by its own marker: `setBlockType("h2")` on `a` in `- x` / `  - a` / `  - b` gives `- x` / `## a` / `- - b`, and on `10. a` / (blank) / `    b` gives `## a` / (blank) / `10. b`, rather than leaving `b` behind as indented code. A heading is written one line per line of text. Turning a list off makes each item's text a paragraph of its own (`- a` / `- b` gives `a`, a blank line, `b`), a task item's marker written as the text it shows (`- [x] a` gives `\[x\] a`). Turning one on makes each selected line an item, the paragraph's lines below the selection continuing the last one; the new items stand line after line as one tight list, written with the marker of the list of that kind they join — the one around them, else the one right before them, else the one right after — and the blank lines between them and a tight list are removed, since they would make it loose. Where joining would change how the list next to them reads — its last line ends in trailing whitespace, an indented code block or a fence left open — the new items are written as a list of their own (`-`, or `1.` counting from one) where they stand. An item that changes kind keeps its task marker (`- [ ] a` gives `1. [ ] a`), and `setBlockType` carries a marker as the list toggles do, into a code block as it was written. `insertTable` goes above the whole block holding the caret — a paragraph, an HTML block or a table, never inside one — and the paragraph commands step out of the top-level quote, list, table or code block around the caret. Each checks its result like the inline commands: when the edited text would not read as the same text in the same blocks with only the intended change, a converted block is first set apart by blank lines (so a paragraph does not join the text or definition around it) or has a character that would open another block escaped (`\~~~`), and failing that the command does nothing — as it does on a line of a table, an HTML block, a definition, indented code or a code block not selected whole, on a `:::` fence or `|||` line, on source the viewer does not show (a repeated definition, a line after a fence closed inside a nested quote), and for a table inside a list item's or quote's content past its first block.

For Markdown written as the editor saves it, the list toggles and `setBlockType` give the same result on both surfaces for the same blocks, but for the differences listed here. One of them is to go: what a list item holds after its text — a further paragraph, a quote, a code block — leaves the list with the text on the WYSIWYG surface (or becomes the blocks of the new item), and stays in the list in source mode, in an item of its own that the item's marker re-opens (the bulleted toggle on `one` in `- one` / (blank) / `  second` gives `one` / (blank) / `second` on the WYSIWYG surface and `one` / (blank) / `- second` in source mode); from a nested list source mode re-opens every list item around the lifted text, where the WYSIWYG surface puts what followed one level up; and where what stays behind would not read as it did under the re-opened marker, the source-mode commands do nothing while the WYSIWYG commands act. A task item's marker re-opens a plain item, so source mode leaves alone the text of a task item that holds further blocks or a nested list, and every block or nested item inside a task item that has more of that task item after it (`b` in `- [x] a` / `  - b` / `  - c`); the last block of a task item converts on both surfaces. A list marker before a thematic break written in the marker's own character reads as a break outside the list (`- ---`), so source mode leaves alone a block that stands right before such a break in its item (`---` or `- - -` in a `-` list, `***` in a `*` list; before `***` in a `-` list, or with another block in between, it acts). A command over several blocks does nothing in source mode when one of them is such a block.

The others come from the surfaces holding different things: source mode can select single lines of a paragraph or of an item's text and makes each selected line an item, where the WYSIWYG surface holds one block; a heading type on a block of several lines makes each line a heading of its own in source mode and the block one heading on the WYSIWYG surface (`setBlockType("h2")` on `one` / `two` gives `## one` / `## two` in source mode and `one` / `two` / `---` on the WYSIWYG surface), and on a heading written with a setext underline — the form such a heading is saved in — the source-mode list toggles do nothing, where the WYSIWYG toggles make it an item; in a block that holds a backslash line break (`one\` / `two`), the source-mode list toggles do nothing when the selection takes the line after the break, and its heading types do nothing at all, where the WYSIWYG commands convert the block as one; on a code block, and on an HTML block, a link reference definition or a thematic break (raw Markdown blocks on the WYSIWYG surface), the WYSIWYG commands convert the block's text — a toggle makes it an item — where source mode does nothing, but for `setBlockType` on a fenced code block at the top level whose lines are all selected, and a thematic break inside a selection is converted with the others on the WYSIWYG surface and stays where it is in source mode; what else the WYSIWYG surface keeps as a raw Markdown block — a blockquote holding a list or more than one paragraph, a list written tight with a block right under another (`* # alpha` / `  1. beta`) — is one block of text there, so the WYSIWYG commands act on it as a whole (a toggle makes all of it one item), a new item beside such a list starts a list of its own, and such a list nested in an item leaves with the item's text like any block the item holds, where source mode acts on the lines the viewer reads in it, joins the new item to the list and keeps the nested list in its item; `setBlockType` on a block a list item holds after its text, or on the heading it opens with, converts it in place on the WYSIWYG surface and takes it out of the list in source mode; `setBlockType("code")` over several blocks makes one code block per block on the WYSIWYG surface and one for all of them in source mode; in a `:::` block of a list item, and for a selection that runs from one `:::` column into the next, the WYSIWYG commands act and source mode does nothing; an empty list item inside a selection is converted with the others on the WYSIWYG surface and left alone in source mode; and a list left as one item that holds only a nested list keeps a loose list's spacing on the WYSIWYG surface.

Markdown the editor would not write itself — which the WYSIWYG surface saves in its own spacing, whatever the command — has further cases, all of one kind: source mode finds no form of the edit that reads back as intended and does nothing, where the WYSIWYG command acts. These are a tab on an item's marker line (right after the marker when the item holds further lines, or inside the text), for commands on that item's text; a block or a nested list of an item indented with a tab, for commands on it and on any block before it in the item; a list toggle on text that opens with an unescaped `[ ] ` or `[x] `, which the new item would read as a task marker (the editor writes `\[ \]`), and any command on the block right before such text in a list item; and indentation that would make the lines after the result read otherwise — a list whose markers are indented, a block standing indented below an empty list item, an HTML block indented deeper than its item's content. Where an item's marker stands on a line of its own, source mode converts the text and leaves the emptied marker behind as an empty item, which the WYSIWYG surface removes.

The three style setters write the `[text]{…}` styled span straight into the raw text, inside any emphasis around the selection (`**[hello]{color=…}**`, the form WYSIWYG saves), merging into a span already around the selection, writing neighbouring text that ends up styled alike as one span, and removing the group entirely when the last attribute is cleared; the attributes are re-emitted in the dialect's own `color`/`font`/`size` order, so a hand-written group may be re-ordered once, and an attribute the dialect does not model is kept as written, after those three. They refuse a selection that crosses a line break, touches a link of any form or an image (its alt text, destination, or `{width=… height=…}` group), lies in a code span, a code block, a `:::` fence line or a table delimiter row (whose `{…}` groups a span would break), cuts through a run's markers (`world** again` in `**hello world** again`), or would put a bracket straight after an escaping backslash (`C:\Users` — the bracket would be literal, leaving the span syntax visible). When a style command covers more than one span, the selection it leaves spans the `]{…}[` syntax between them; a format toggle pressed straight afterwards does nothing, since its markers would cut those spans, so reselect text inside one span before toggling a format.

## Dirty state

The editor reports itself dirty, via [`Component.isDirty()`](/api/core/classes/Component), whenever `getValue()` differs from the Markdown at the last clean point — the clean point is the value it was constructed with, or the value `markClean()` last accepted. Both surfaces go through the same check, so an edit undone back to the clean text clears the flag on its own, and a mode switch that changes nothing textually does not set it. `isDirty()` folds up into every ancestor container automatically. A host that loads a document with `setValue()` should follow it with `markClean()`, so the loaded text becomes the clean text.

One corner case: a `markClean()` taken in source mode over text the WYSIWYG surface cannot save as written — `\r\n` line endings — marks the editor dirty on the next switch to WYSIWYG — the value the host would save really did change.

## Read-only

`setReadOnly(true)` locks the editor against edits (dropping the caret and editing affordances); `false` restores them. While read-only the WYSIWYG surface is not `contenteditable`: its text can still be selected with the mouse and copied, but it shows no caret and takes no keyboard focus, so its context menu, which then offers only Copy, opens from a right-click and not from the keyboard. Read-only wins over `setContentEditable(true)`, which takes effect once the editor is editable again: `setReadOnly(false)` gives the surface whatever `setContentEditable` last asked for. The source surface keeps its caret and keyboard selection while read-only, as `CodeEditor` does.

Read-only also refuses every command that edits the document, on both surfaces: a call such as `toggleBold()`, `insertTable()` or `cut()` leaves the document and the selection as they are, and `paste()` resolves `false` without reading the clipboard. `copy()` still copies. `getSelectionState()` then reports every `can…` field `false`, and `"selectionstate"` fires when `setReadOnly` changes them, so a toolbar built on those fields greys out — as [`MarkdownDocumentPanel`](/components/MarkdownDocumentPanel)'s does, its Table button included, which reads `canEditTable`, `canMergeCells` and `canUnmergeCell`. `inTable` is not such a field: it says where a caret or a text selection is (it is `false` while whole table cells are selected, and for a selection that runs out of its table), and stays `true` in a read-only editor's table cell, so a control enabled on it alone would stay enabled. Replacing the whole document with `setValue()` stays possible, as on a read-only `CodeEditor`: read-only guards against edits, not against the host loading another document. To change a read-only editor's document from code, load the new text with `setValue()`, or lift the lock around the command.

For a purely *display* use case, prefer the leaner [`Markdown`](/components/Markdown) viewer, which needs no Lexical — `MarkdownEditor`'s read-only mode is for temporarily locking an editor, not for replacing the viewer.

A source-mode command refused because the editor is read-only flashes the source `CodeEditor`, the same feedback a rejected keystroke gets, `cut()` and `paste()` included; the WYSIWYG surface has no such flash and refuses silently. That editor fires its own `"readonlyedit"` event, but it is `MarkdownEditor`'s private child: `MarkdownEditor` neither exposes it nor re-emits the event, so there is currently no public hook for the refusal.

## Theming

The editing surface's class rules reference the same CSS custom-property tokens the viewer uses (`--ts-ui-font-mono` for code, `--ts-ui-border-color` for the quote bar, `--ts-ui-indicator-focus` for links), so a [`ThemeManager.setTheme`](/api/core/classes/ThemeManager) toggle recolours it immediately with no rebuild, and the edited rich text visually matches what the viewer renders.
