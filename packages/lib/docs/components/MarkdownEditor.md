# MarkdownEditor

[`MarkdownEditor`](/api/component/editor/classes/MarkdownEditor) is a **WYSIWYG rich-text editor whose public value is a Markdown string**, built on [Lexical](https://lexical.dev/). You edit a document as rendered rich text — no visible markup — and read or write it as Markdown through `getValue()` / `setValue()`. It is the editing counterpart to the read-only [`Markdown`](/components/Markdown) viewer.

Its dialect is deliberately the **exact subset the viewer renders** — headings, paragraphs, bold, italic, underline, inline code, coloured/sized/font-styled spans, ordered/unordered lists, blockquotes, fenced code, links, reference links, GFM pipe tables (with per-column alignment, widths, and merged cells), and `:::` block-alignment / explicit column-region fences. The editor reads Markdown with the viewer's own parser and writes it with its own serializer, so **a document saved by the editor renders in the viewer as the editor showed it**.

Lexical's editing view is a `contenteditable` element it owns and mutates directly — a *foreign live widget*, like the CodeMirror view behind [`CodeEditor`](/components/CodeEditor) — so the view mounts through the framework's DOM seam once the component is connected and sized. Unlike a code editor, Lexical keeps its editor **state** (a pure, DOM-free tree) separate from that view, so the Markdown value get/set/round-trip runs headless: offline the view never attaches, yet `getValue` / `setValue` and the command API still operate on the state.

## Usage

```typescript
import { MarkdownEditor } from '@jimka/typescript-ui/component/editor';
import { Fit } from '@jimka/typescript-ui/layout';

const host = new Panel({ layoutManager: new Fit() });
const editor = new MarkdownEditor('# Title\n\nSome **bold** text.');

host.addComponent(editor);
editor.on('change', ({ value }) => console.log(value)); // value is Markdown
```

`lexical` and the `@lexical/*` packages are runtime dependencies of the library, installed transitively when you install `@jimka/typescript-ui` — the same as `marked` for [`Markdown`](/components/Markdown). A consumer who never imports `@jimka/typescript-ui/component/editor` never bundles Lexical.

Give the editor a sized host (a `Fit` panel, as above, or an explicit `preferredSize`) — it fills its assigned box and scrolls internally, exactly like `CodeEditor`.

## Construction

`MarkdownEditor(value?, options?)` — the initial Markdown `value` is an optional positional argument (equivalent to the `value` option).

| Option | Type | Default | Purpose |
| --- | --- | --- | --- |
| `value` | `string` | `""` | Initial Markdown source. |
| `readOnly` | `boolean` | `false` | Whether the editor rejects edits. |
| `mode` | `"wysiwyg" \| "source"` | `"wysiwyg"` | Which editing surface is shown — see [Source / WYSIWYG mode](#source-wysiwyg-mode). |
| `listeners` | `{ change?: (payload) => void, selectionstate?: (payload) => void, readonlyedit?: () => void }` | — | Construction-time listener bag for the `"change"`, `"selectionstate"` and `"readonlyedit"` events. |

Inherits the common [`ComponentOptions`](/api/core/interfaces/ComponentOptions) fields (preferred size, background, foreground, etc.).

## Supported constructs

The editor edits, and emits, only the constructs the [`Markdown`](/components/Markdown) viewer renders. The table gives the standard form an edited block is written in; a block left unedited saves as it was written (see [Common methods](#common-methods)):

| Construct | Markdown emitted |
| --- | --- |
| Heading | `# ` … `###### ` |
| Paragraph | plain text |
| Bold | `**bold**` |
| Italic | `*italic*` |
| Inline code | `` `code` `` |
| Unordered list | `- ` (an authored `*` or `+` is kept) |
| Ordered list | `1. ` (an authored `1)` is kept) |
| Task item | `- [ ] `, `- [x] ` — a checkbox first in a list item's text; a loaded `[X]` is kept; one space follows the marker once its item is edited; see [What Markdown cannot hold](#what-markdown-cannot-hold) for where a checkbox can stand |
| Blockquote | `> ` |
| Horizontal rule | `---`; a loaded rule keeps the line it was written with (`***`, `* * *`, `___`), without its indentation once its container is edited — see [Horizontal rules](#horizontal-rules) |
| Fenced code | ` ``` ` fence; `~~~` when its info string holds a backtick; a loaded info string keeps the words after its language |
| Strikethrough | `~~struck~~` |
| Underline | `++underlined++` |
| Coloured / sized / font-styled span | `[text]{color=... font=... size=...}`; a loaded span keeps its attributes' order and any it does not style with |
| Link | `[text](url)`; text entered at a link's very start or end — typed, pasted, or composed with an input method — is ordinary text outside the link |
| Reference link | `[text][label]`, `[label][]`, `[label]` as written — see [Reference links](#reference-links) |
| Table | pipe rows plus a `\| --- \|` delimiter row |
| Table column width | delimiter cell's trailing `{width=240}` |
| Merged table cell | body cell's `<<` (from the left) / `^^` (from above) |
| Block alignment / column region | `::: {align=... gap=...}` … `:::`, columns split by `\|\|\|`; a loaded fence keeps its opening line as written — words the viewer ignores (`::: tip Title`) and its attribute group, which is rewritten only once the fence's alignment or gap changes |
| Image | `![alt](src "title"){width=... height=...}`; a loaded image keeps the form it was written in — its title's quotes, a `<…>` destination, a reference's label and form, the syntax of its alt text — while that form still reads as the image, and its attribute group as written while its size is unchanged; a reference image whose definition no longer gives its source and title is written inline, so a save never changes where an image points; the bold, italic, strikethrough or underline marks an image was read inside are written back around it, and **Clear formatting** over it takes them off |
| Underscore emphasis | read; written as `*` / `**`, or as `_` / `__` around emphasis whose own `*` the viewer would pair with it |
| Setext heading | read; written `#`, or still setext (`===` / `---`) when its content spans lines and no line of it would read as a code fence or HTML block |
| Indented or `~~~` code | read; written as a fenced code block |
| Autolink | `<https://…>`; a bare URL, `www.` address or email address loaded from the document stays bare |
| Hard line break | `\` + newline (Shift+Enter, except where Markdown has no break — see [What Markdown cannot hold](#what-markdown-cannot-hold)); an imported two-space break keeps its spaces |
| Character reference | read as the character it names (`&copy;` shows `©`) wherever the viewer reads it; written as the character itself, and text that would read as a reference is written with its `&` escaped (`\&copy;`); a no-break space is written `&nbsp;` where Markdown would trim it: at the edge of a heading (a setext heading's lines too), a table cell (each of its paragraphs) or a list item, and as a line holding only it; elsewhere, a paragraph's line edge included, it is written as itself |
| Markdown punctuation in text | a line-start `#`, `>`, `-`, `+`, `*`, `_`, `~`, `` ` ``, `=`, `|`, `:` or list number, and a `*`, `_`, `~`, `` ` `` or `++` that could pair with another, keep their backslash only where they would start something there (`\- x`, `\# x`, `\*x\*`), and an `&` that starts a character reference (`\&copy;`, `\&#35;`); `--- tail`, `#tag`, `a * b` and `===` stay bare. Brackets (`\[label\]`), `<`, `\`, a `!` before a link, table pipes, the punctuation of bare URLs and addresses, and every character in a link's or styled span's text, in a table cell of several paragraphs and in joined Markdown always keep theirs |

Images, sized via the same `{width=… height=…}` grammar as a table column width, **are** part of the dialect, authored through `insertImage` or the empty-line context menu's **Image…** item. An `<img>` pasted from a web page is an image, its `title` kept. A column's alignment (from the delimiter row's `:---` / `:---:` / `---:` markers), its width, and merged cells are all **preserved** across a load/edit/save round-trip and all authorable in the WYSIWYG surface, through `setTableColumnAlignment` / `setTableColumnWidth` / `mergeTableCells` / `unmergeTableCell` and the table-cell context menu's Align column/Column width…/Merge cells/Unmerge cell items.

### Horizontal rules

A thematic break (`---`, `***`, `___`, with the spaces, tabs and up to three spaces of indentation CommonMark allows) is a **horizontal rule**: a block of its own that shows a line, holds no text, and is selected and deleted as one unit. It stands wherever the viewer renders one — at the top level, in a list item, in a quote and in a `:::` column — and a table cell drops one, since Markdown has none there. A loaded rule is saved as it was written; a rule made in the editor is written `---`.

- **Selecting.** A click on a rule selects it, drawn with the accent ring. The arrow keys select it from the block before or after it (ArrowRight at the end of the line above, ArrowLeft at the start of the line below) and move the caret out of it again. Typing on a selected rule changes nothing; Enter opens a paragraph after it.
- **Deleting.** Backspace at the start of the block after a rule and Delete at the end of the block before one remove the rule, also when the rule ends a list or a quote that stands right before the block, or opens one that stands right after it; Backspace in an empty paragraph after a rule removes the paragraph and selects the rule, and Backspace or Delete on a selected rule removes it. A range that starts right before a rule or ends right after one (what Select All makes in a document that opens or ends with one) takes the rules between its two ends with it, and no rule beside it: a range over one rule among several removes that rule alone. Ctrl/Cmd+Backspace and Delete and the line deletes act beside a list or quote ending or opening with a rule as Backspace and Delete do. One undo brings a deleted rule back, selected.
- **Copying and pasting.** A selected rule counts as selected text: Cut and Copy are enabled, and copy writes the rule's line. A rule copied in the editor pastes as a rule, and an `<hr>` pasted from a web page is a rule. A paste with a rule selected replaces the rule where it stands, in the rule's own parent (the document, a list item, a quote or a `:::` column), and never splits that container: pasted blocks go in at the rule's place, pasted inline content (a copied word) and plain text go in as paragraphs, one for each line.
- **Commands over a range that crosses a rule.** A link over such a range links the text of each block and leaves the rule, as the format toggles and the text styles do. A command that would change nothing (a paste of an empty clipboard, a screenshot or no nodes) leaves the rules at the range's ends and the selection as they are; Shift+Enter removes the range, the rules at its ends with it, as Delete does, and adds the break only where the caret that leaves has a place for one. A rule pasted at the end of a list item's text is the last block of that item (in front of the item's nested list, when it holds one) and leaves no empty item after it.

### Reference links

A reference link — `[text][label]`, `[label][]` or `[label]` — is a link in the WYSIWYG surface, edited like any other, and is saved in the form it was written **while the label's definition in the saved document gives the link's URL and title**, matching labels as the viewer does (case and runs of whitespace aside, the first definition of a label winning). Once the link's text is edited or formatted, a `[label]` or `[label][]` reference is saved as `[text][label]`. Once the link's URL is changed (**Edit link…**), or its definition is edited, removed, or no longer the first for its label, the link is saved inline as `[text](url "title")` with its own URL — so **a save never changes where a link points**. A `[label]` reference is written `[label][]` where the character after it would otherwise join it to another construct (a `(`, `{` or `[`, or a `:` at the start of a block), and where it opens a list item's text as `[ ]`, `[x]` or `[X]`, which would read as a task checkbox. A link whose title holds a blank line keeps its reference form while its definition gives its URL, and takes the title its definition is edited to; one copied in from another document, whose title the document's definition does not give, is saved inline with the title it shows (written `&#10;&#10;`), as an image is. A definition counts wherever the viewer reads one — in a list item or a `:::` column too, also right after an HTML block left open there, which ends with its item or column — and the first definition of a label in the document is the one that counts.

Definition lines (`[label]: url "title"`) show as raw Markdown blocks (see below) and are saved exactly as written; a run of definitions on consecutive lines is one block, and a blank line ends the run, also when it is typed into one.

Editing the definitions changes what the editor shows only where the viewer would show something else. Text never becomes a link: a `[label]` you type, inside a link's text or not, is saved with both brackets escaped (`\[label\]`), so a definition added for it later leaves it text and cannot hide the emphasis around it. A reference link keeps its own URL, as above. A reference kept as written — one with empty text (`[][label]`), a reference inside a construct kept as source — shows what its definition gives it, so when a definition it uses is typed, edited, pasted or removed, its block shows what a save and a reload would show: the reference whose label no longer resolves shows as its text, and from then on is text.

A reference image keeps its own source and title as a reference link keeps its URL: it is saved in whichever form it was written in (`![alt][label]`, `![label][]` or `![label]`) while its label's definition gives them, and inline otherwise.

### Kept as source

Markdown the editor has no rich-text form for is kept as source and saved exactly as written. HTML blocks and link reference definitions load as a **raw Markdown block** — shown in a monospace font, editable as text, saved exactly as written (once edited, without an empty first or last line and without the up to three spaces of indentation before it, which mean nothing to Markdown and would move it into a list above it; they stay where a line of the block is read by them, as the lines of a raw list's first item are) — and so does a whole list when it is tight — no blank line between its items or between an item's blocks — and an item holds a block right under another (`- a` over an indented `> q`; a nested list right under its item's text is no such block), or when an item holds Markdown the editor keeps as a raw block that would not read the same wherever it stands in the item — a quote that ends on a line without `>`, indented no deeper than the quote, that starts an HTML block (`> q` over `<div`: the viewer reads that line as part of the quote or as a block after it, depending on what follows the item), or text that only reads as it does with spaces before its first line, and a table whose body row holds more cells than its header (cells the viewer drops). A blockquote loads as a raw Markdown block only when one of its lines without `>` — a lazy line — falls in a block other than a paragraph (`> q` over an indented `<div`, `> - a` over `b`): such a quote reads by what follows it. Inline HTML, images the viewer will not render (which show nothing, as in the viewer), and links a link node cannot hold — one with empty text (`[](url)`), or whose whole text is another link (`[<https://a.test>](/b)`, which shows the inner link's text linked and formatted as the viewer shows it) — load as **atomic runs** that show what the viewer shows and save unchanged; a soft line break inside a paragraph is one too, showing as a space and saving as the line break it was. A `<br>`, `<br/>` or `<br />` in a table cell is no atomic run but a line break, so once its cell is edited it is saved as `<br>` outside the marks around it: `**a<br>b**` becomes `**a**<br>**b**`, and every other form (`<br/>`, `<br />`, `<br >`, in any letter case, such as `<BR/>`) becomes `<br>`; it reloads as it shows. The format toggles, text styles and links decline over a selection holding an atomic run other than a soft break (its source would not save the format the way it shows), and the link commands decline inside a link shown this way. No block stays inside a block that holds text only — a paragraph, a heading, a code block or a raw block. Joining a list item to the block before it (Delete at that block's end, a range deleted from that block into the item; Backspace at the start of a list's first item turns the item into a paragraph first) joins the item's text to it, and the blocks the item held follow it as blocks of their own, in order. A raw block and a code block hold only text: inside one, Enter adds a line (at a raw block's end it starts a new paragraph after it, at its start one before it), pasted content goes in as plain text (each block an item of a pasted list holds apart from the item's text, as two items are), and Backspace at the start of a paragraph, heading, quote or list item's text after the block (or Delete at the block's end) joins it as its Markdown; the typing shortcuts do not apply there, and the format toggles, text styles, links, images and tables decline, since the block saves its text as written. A selection that runs from inside such a block into another block is removed the same way by every edit that replaces it — Delete, Backspace, a word or line delete, a cut, typing, an input method, Enter, Shift+Enter, Tab, a paste and a drag that moves it — whichever way it was made: the rest of the block it ends in joins the raw block or code block as its Markdown (as its text, when that block is a raw block or a code block too: its lines are left as they are, and only where a code block's or HTML block's text lands at a line start of the raw block is that first line changed — its leading whitespace is kept as far as the line still reads as the text, and a first character that would make a heading or a code block, such as `#` or a fence, gets a backslash), so its formatting, links and escaped characters keep meaning what they showed: a code block takes the rest as that block's own line holds it (`### +alpha` gives `+alpha`, and a no-break space is the character itself, not `&nbsp;`), a raw block as Markdown with every escape, escaped for where it lands (a `>` that would close a tag the raw block's text leaves open is escaped too: `<br` at the end of a quote's line joined with `/>cd` is written `<br/\>cd`, and at the end of a list item's own line `\<br/>cd`, which reads as text too), and where the rest opens one of the raw block's lines — at its start, or after its quote or list markers — the spaces and tabs it opens with are kept only as far as the line still reads as the rest's own text (four columns of them would make it a code block), and a list item the selection empties is kept as an empty item, written `*` where a bare `-` under a line of text would read as a heading's underline; a raw block whose text then reads as other blocks shows as those blocks; and what the edit inserts goes in at the caret that leaves, as it would after Delete. A selection that runs into such a block from a block before it is removed first too, and what is left of the raw block or code block joins that earlier block as text. A selection inside one raw block or code block is edited as text: what is typed or pasted replaces it in place, and a raw block is read again afterwards. Shift+Enter over a selection that leaves such a block removes it the same way, then adds the break only where the caret that leaves has a place for one (see *Line breaks* below). Converting a block to a code block keeps its formatting, links and images as their Markdown in the code. The code holds the block's text as the block's own Markdown writes it: a heading's text as its line holds it, so `### +alpha` gives a code block holding `+alpha` and `# alpha \#` one holding `alpha \#`, where a paragraph saved as `\+alpha` gives `\+alpha`. A raw block keeps the indentation `marked` reads its lines by when removing it would change what the block is. That holds for each of its lines: a quote whose last line stays in it only while indented (`> q` over an indented `<div`) keeps that line's indentation, in the document, in a `:::` column and in a list item. An HTML block its own text does not close (`<!--` without `-->`, `<pre>` without `</pre>`) takes in everything after it in Markdown, so while blocks follow it in the editor — in a list item, also the item's nested lists — it saves as a paragraph of the same text — its first `<` escaped, its lines kept by line breaks — and the blocks after it stay their own; the editor then shows it as that paragraph, the moment an edit leaves its text open with a block after it, or a block is added after it. A raw block in a `:::` column — one of its blocks, or a block of a list item there — whose text holds a line the fence would read — a `:::` line, a `::: …` opener, a code fence it leaves open, or a `\|||` line — saves as a paragraph of the same text for the same reason, and the editor shows it as that paragraph: this is what an HTML block holding `:::` becomes when `setBlockAlignment` or `setColumnCount` wraps it, or when it is pasted or typed into a column. Likewise a paragraph loaded from a `::: …` line whose fence had no closing line — the fence then reads as ordinary text — is saved with that line escaped (`\::: …`) once a block after it holds a `:::` line that would close the fence. Enter or a line break with the caret inside an atomic run lands after it; typing there replaces the whole run, and Backspace deletes it whole. A raw block left holding nothing — all its text deleted, or removed by a selection that runs on into a later block — shows as an empty paragraph, which takes the caret, so what is typed or pasted next is rich text; Shift+Enter over a selection that would leave nothing but the break removes the selection and adds no break. When a raw block's text is edited until it reads as more than one block — a blank line typed into an HTML block, a fence pasted into an HTML block's text — or as one block the editor holds as rich text — a tag a deletion broke, leaving a paragraph; the halves of a link reference definition a paste split, each now a paragraph of text — the editor shows it as the blocks it saves as, with the caret where it was in the text: everything those blocks show is on the side of the caret its source was on, so a space that shows stays where it was, and what is typed or pasted next goes in at that place. Between text in two formats the caret is in the one its place had in the source — inside the delimiters of bold text it is in the bold text, outside them in the text beside it. A space that ends the raw block's text before a removed range goes with it when nothing follows the joint: the block shows as its save reads it, and a save does not write a space that ends a block, so what is typed next follows the text. Where the item of a list or the cell of a table that holds the caret shows nothing, the caret stays in that item or cell, never in the text of the one beside it. The caret goes to the end of its block only where the block shows nothing at all, or where it holds, beside the caret or after it, text whose place in the source the editor does not find, because Markdown's lexer hands that text back otherwise than it is written: an HTML line whose container prefix holds a tab, a code line holding a tab that `marked` reads into a quote CommonMark ends there, or a paragraph line made of list markers and tabs, which show as the spaces the tabs stand for, a task item whose checkbox is followed by more than one space in a list with blank lines between its items, or text of a list item that begins as a link reference definition repeated before it does.

An inline construct the editor's own way of writing would read back differently — strikethrough over a space before a linked image, a bare URL in a heading whose id it is part of, a styled span with an attribute the editor drops — loads as atomic runs that keep its source: only the construct is kept, the text around it stays ordinary text, and the construct saves exactly as written. Clearing formatting over it keeps the formats its source writes. An edit that takes such a construct apart turns what is left of it into ordinary text, shown and saved as that text.

### What Markdown cannot hold

Some states a rich-text editor can make have no Markdown form: a save would write them differently from how they look. The editor does not make them, so what it shows is always what it saves.

- **Line breaks.** Markdown has no hard break at the end of a block, in a block holding nothing else, or in a level 3–6 heading (an ATX heading is one line; levels 1 and 2 save multi-line as setext). Shift+Enter does nothing there, and over a selection it removes the selection, as Delete does, and adds the break only where the caret that leaves has a place for one; a break another edit leaves at a block's end is removed, and one in a level 3–6 heading — a pasted `<br>`, a code block's lines when it becomes a heading — shows as the space it saves as, and so does one in a level 1 or 2 heading when a line of its setext form would read as a code fence or HTML block, which saves it on one line. A table cell keeps every break, anywhere in the cell: Shift+Enter there makes a line break, saved as `<br>`, and Enter a new line of the cell, saved as the cell paragraph break `\n\n`; both show as a new line, and a `<br>` in a loaded cell shows as a line break. A code block's lines, when it becomes a paragraph or a list item, are kept by line breaks. An empty line among them is saved as a line holding only the `\` of its break (`a\`, `\`, `b`), as two line breaks in a row are anywhere; it reloads as the same empty line.
- **Bold, italic, strikethrough and underline at a run's edge.** Their delimiters cannot stand against whitespace inside them, nor against punctuation inside them with a letter outside (`x**(a)**b` reads as literal asterisks). Applying one of them trims the selection's edge spaces off it and does nothing on whitespace alone, and a selection reads as having it — on the toolbar, in the context menu and to the next toggle — when everything in it but the whitespace the format would be trimmed off carries it, so a second press over the same selection takes it off again; taking one off part of a run leaves the spaces around it plain. A format whose result still could not be saved as shown — emphasis, strikethrough or underline opening with punctuation right after a letter or closing with it right before one — is declined, from a toggle, the keyboard shortcut or a typing shortcut alike (`x**(a)**` typed stays text). After a paste, a deletion, a cut, a split or typing, the formats are taken off such whitespace and punctuation instead: a space typed after bold text shows plain until the next word joins the run, and a word typed right before emphasis that opens with punctuation takes that emphasis off its edge.
- **A colour, font or size over `[` or `]`.** A styled span's grammar cannot hold a bracket. The setter that would make one is declined; a bracket typed or pasted into styled text shows without the style, as the save writes it.
- **Whitespace at a line's start.** Markdown drops the spaces and tabs a line starts with — at the start of a paragraph, heading, quote, list item or table cell paragraph, after a line break, and after a task item's checkbox — so the save writes none. A space typed there shows while the caret stays right after it; the next edit of the block removes it, so a letter typed after the space takes its place. Whitespace another edit leaves at a line's start goes at once unless the caret stands right before or after it: a pasted line that opens with a tab loses the tab, while a space left right after the caret by Enter or a deletion stays, and text typed there keeps it inside the line. A code block, a raw Markdown block, a code span, a link's text, styled text and a cell's line after a `<br>` keep theirs, as their save does, and so does the indent before a source run, such as an indented `<span>`, that opens a later line. A heading written on one line has no later line: its line breaks are spaces. Whitespace another edit leaves goes at once only in the block that holds the selection.
- **Task items.** A checkbox stands only first in a list item's text, and anywhere else becomes the text it saves as (`[x] `), as it does when its text leaves its list: a line break that moves it off the item's first line, a paste in the middle of a paragraph and a block conversion all leave it as text. A task item with no text after its checkbox has no Markdown form (`- [ ]` reads as an item holding the text `[ ]`): it keeps the checkbox while the caret is in it, so Enter can open a task item and its text be typed, saves as `- [ ]` (`- \[x\]` when checked), and once an edit of it leaves the caret elsewhere shows that text. One loaded with a character reference for a space after its marker (`- [x] &#32;`), which the viewer shows as a checkbox alone, keeps the reference: it stays a checkbox, toggled or not, and saves with the reference (`- [ ] &#32;`). Text after a checkbox that opens with a space other than an ASCII one, such as an ideographic space, saves that space as a character reference (`- [x] &#12288;a`), so a reload still reads a task item. A code block made from a task item with no text holds its marker as the item showed it (`[x]`). A caret before a checkbox acts as the caret right after it: typing, pasting, Enter and Backspace there act after the checkbox, and so they do with a caret code sets on the task item itself, before its text; with the caret before the checkbox or right after it, `insertTable`, `insertHorizontalRule` and a pasted table or rule put their block above the item, which keeps its checkbox. An insert or a pasted block that splits a task item's text gives the text after it an unchecked checkbox, as Enter does. A link over a range that takes in a checkbox links the text after it, never the checkbox. The blanks that end a list item's text show as none, as the save writes none.
- **A link holding only a soft line break** at a block's edge, where the save drops it, is unwrapped.
- **Lists.** A change of bullet character or ordered delimiter starts a new list (`- a` then `+ b` are two lists), and the editor keeps such lists apart; lists of one marker made next to each other in the editor join, as Lexical joins them, and two a document loads apart (after an empty item) stay apart. Two raw list blocks an edit brings together, which the viewer would read as one list, are saved with a `[//]: #` line between them, a link reference definition that shows nothing; so are two inside one list item. A raw block an edit emptied counts as nothing between a list and a raw list. A list's looseness follows what its save reads as: a list left with one item of one block is tight, and a list whose item holds a block after its nested list is loose. A nested list follows its item's text directly and any other block of the item — a table, which would read its lines as rows, or a paragraph, which would take in an ordered list not starting at 1 — after a blank line, which makes the list loose; two nested lists of one item, or a nested list and a raw list next to it, that the viewer would read as one are saved with another bullet or delimiter. A list item holds blocks as the viewer shows them: further paragraphs, headings, code blocks, quotes, tables, `:::` fences and raw Markdown blocks (a link reference definition among them, also one repeating an earlier label, which Markdown ignores) load as blocks of the item, before or after its nested lists; a run of definitions on consecutive lines is one block there too, and a blank line between two definitions makes them two. A nested list that itself loads as a raw Markdown block is such a block of its item, and the list around it loads by the same rule as any list. A raw Markdown block in a list item follows one rule: its text, saved from its first line that holds something to its last and without the spaces before it that mean nothing to Markdown, must read in the item exactly as it reads on its own, wherever it stands there. A list loads with such a block only when that holds, and when an edit leaves raw text for which it does not — spaces typed before a raw list whose lines are measured by them — the editor reads the whole list again as its save reads, so it shows what loading that save shows (the list may then show as a raw block). Pasting several blocks into a nested list item, `insertTable` or `insertHorizontalRule` at a nested item's text, or **Insert line after block** inside a nested list, adds such a block to the outer item, and it is kept through a save and a load. At the end of the text of an item holding a nested list, a pasted or inserted block goes into the item, in front of that list. A list that is copied and pasted keeps the paragraphs its items hold, and a format the editor declines on an item's text leaves them as they were. An edit of an item's own text leaves the blocks the item holds as blocks: Enter in that text moves what follows the caret into the new item, the item's blocks with it; text typed or pasted over all of that text replaces it and nothing else; and once an item's own text is deleted, the paragraph after it is its text, as Markdown reads an item whose first line is empty; before any other block — a nested list, a heading, a table — the empty text line stays, to type the item's text in, and Enter on that empty line takes the item out of its list, as Enter in an empty item does. A nested item moved out of its list — Backspace at its start, or a block type or the list toggle set on it — takes along the blocks the outer item holds after that list, which follow it as they did before. An item that is indented or moved out keeps its own nested list under it. Joining an item's text to the block before it — Delete at that block's end, or a range that ends in the text — joins the two texts, and what the item held after its text follows into the item before it; for a list's first item, the blocks up to its first nested list follow the text out of the list. A range that takes an item's text whole and ends in a later block of that item — a further paragraph, a heading, a quote, a code block, a table, a `:::` block or a nested item — follows the same rule, whichever edit removes it: the item goes, and what the range leaves of it follows into the item before, so no bullet is left without its text line; an item nested in it whose text the range takes too is joined away the same way. Where nothing would join the item's text — the range starts in a table cell, in a `:::` column the list is not in, or between two blocks — the item stays and keeps what is left. Backspace at the start of an item's further paragraph joins it to the block before it. A block type set on such a further block changes it in place; set on the item's own text, it takes the item out of its lists. A list toggle on an item's own text, or on the heading an item opens with, takes the item out of its lists the same way, or makes it an item of the other kind there. Either way the blocks the item holds up to its first nested list go with the text — after the paragraph, or as the blocks of the new item — and the nested list's items stay in a list where the item's outermost list stood, in the item's place and as siblings (a nested item lifted out of every list sends its own nested items to that level, not under its parent); what followed the nested list goes to the last of them. A list toggle on a further block of an item makes that block an item of its own, with the blocks after it. With an end of the selection between two blocks rather than in a text — `deleteTable()` leaves the caret on a list, a list item, a `:::` block or one of its columns, or on the document itself — a list toggle and `setBlockType` act on blocks of text all the same. A caret there goes into the block of text after it, or the one before it when none follows; a table beside it is passed over, and a `:::` column the deleted table left empty gets an empty paragraph for it. In a document the deleted table left empty, and at a point code sets with a table on both sides, the command makes its block new and empty there. The ends of a range go inward: its start into the first block of text after it, its end into the last one before it, so the command changes the blocks between the two ends and never one outside them; a range with no block of text between its ends acts as a caret where it starts. A range that only covers a column a deleted table left empty leaves that column as it is and changes the blocks of text around it. `deleteTable()` on a table that stands next to another table leaves the caret on that other table, where these commands are unavailable, as they are for any caret on a table. A copy that reaches from an item's text into a later block of the same item — a further paragraph, a nested list — copies the item, holding both. Deleting everything a list item holds — a range from the start of its text to the end of its last block, or `deleteTable()` on a table that is all the item holds — leaves that item, empty, with the caret in it, as deleting the text of two plain items leaves an empty item; a list is never left without one. Backspace at the start of a block after a `:::` block, or after a list whose last item ends in a table or a `:::` block, does what it does after a table: a block that holds something stays where it is and nothing is joined, and an empty block is removed, the caret going to the end of the table's last cell or of the `:::` block's last block. A caret between the blocks of an item, where the arrow keys leave one beside a table and code can set one anywhere, takes Enter, typed text, a paste and an inserted image in a paragraph of that item, and so does a range whose removal leaves the caret there; Shift+Enter changes nothing there, since there is no line to break, and over such a range removes the range and adds no break. A caret code sets on an item right before the item's text stands at the start of that text instead, so every edit there acts as it does at a click before the text's first character. Blocks pasted into a block that a list item holds — one of its further paragraphs or headings, or a paragraph or heading of a quote it holds — become blocks of that item, the block split at the caret, as a paste at the top level splits a paragraph: the text after the caret joins the last pasted block when that is a block of text, and stays a paragraph of its own after a pasted list or table. A list pasted at an item's text leaves what the item holds with the text it followed, in the last pasted item. A paste at an item's text that ends in a table or a `:::` block — a pasted table, or a pasted list whose last item ends in one — leaves the text after the caret an item of its own after the pasted blocks, with the blocks its item held, as a table inserted at that caret does; with nothing after the caret, or blank text alone, no empty item is left. A horizontal rule of the bullet's own character that opens an item (`---` in a `-` list) is saved under the marker on a line of its own, since `- ---` is one thematic break.
- **Tables.** Two paragraphs of a cell are saved with `\n\n` (a backslash and an `n`, twice) between them, the dialect's cell break; a merged cell holds one paragraph per merged cell that had content. A table stays rectangular and aligned by column: a row an edit leaves short is filled with empty cells, a merged cell spans no row past the table's end, a header cell an edit leaves merged (a range deleted from the header row into a merged body row) is split into the cells it covered, since Markdown merges body cells only, every body cell takes its column's alignment (the header cell's, which the delimiter row writes), and a heading, quote, code block or list pasted into a cell becomes the lines of text the cell saves — for a list, each item's text and each block an item holds on a line of its own. Table rows or cells pasted without their table (a range selection set by code that stays inside one table copies them that way; a selection of cells made with the mouse or the keys copies a table) paste as a table holding them does, a short row filled with empty cells: as a new table, or, in a cell of another table, over that table's cells from that cell on. A selection that runs from outside a table into one of its cells covers the whole table, as the editor highlights it: deleting, cutting, typing or pasting over it removes the selected text outside the table and the whole table, and leaves the block on the table's far side as it was (two lists of one marker the table stood between then join, as lists made next to each other do). A cut or a copy of such a selection — from the keyboard, the context menu, `cut()` or `copy()` — puts on the clipboard what the cut removes, the whole table included; a copy leaves the document and the selection as they are, and a selection that crosses no table's edge (inside one cell, over cells of one table, or outside every table) is copied as it stands. `insertTable`, `insertHorizontalRule` and `insertImage` remove such a selection the same way before they insert (the removal and the insertion are one undo step), and where that leaves the caret at a block that cannot take what is inserted — a raw Markdown block or a code block, and for a table another table — the table or image goes into a new paragraph where the removed table was. An edit that changes nothing leaves the selection as it was, as it leaves any other: a paste that inserts nothing (a pasted screenshot, an empty clipboard). Shift+Enter over such a selection removes it as Delete does, the whole table included, and adds the break only where the caret that leaves has a place for one (see *Line breaks* above).
- **Quotes.** A quote holds blocks as the viewer shows them — paragraphs, headings, code blocks, lists, tables, `:::` fences, raw Markdown blocks and other quotes. Enter splits a paragraph of a quote; Enter on an empty line of a quote takes that line out of the quote, one level, splitting the quote there; Backspace at the start of a quote's first block takes that block out the same way. A join across a quote's edge — Backspace at the start of the block after it, Delete at its end, a range across it — joins the two texts, as between two paragraphs. Blocks pasted into a paragraph or heading of a quote become blocks of the quote, the block split at the caret. A caret between two blocks of a quote, which only code can set, takes Enter, typed text, a paste and an inserted image in a paragraph of its own there, as between the blocks of a list item. A block type, a list toggle, `insertTable` and `insertHorizontalRule` act inside the quote; `setBlockType("quote")` puts the blocks into a quote or takes them out of it (see *Command API*). The typing shortcuts for blocks (`# `, `- `, `1. `, `> `, ` ``` `, and the horizontal rule's `---`) apply at the start of a quote's paragraphs as at the top level. An edited quote keeps the lines of its unedited blocks as written, `>` markers included. A quote with a line that does not open with `>` (a lazy line), or with a tab, is written whole in the standard form once it is edited.
- **Columns.** A `:::` column exists only inside its fence. Columns pasted anywhere else — a selection copied across two columns and pasted into a paragraph, another column or a table cell — become the blocks they hold, which is what the save writes, and paste as those blocks would: a block of text (a paragraph, heading, code block or raw Markdown block) that comes first joins the block at the caret, and one that comes last takes in the rest of that block.
- **Empty links.** A link a paste leaves with no text at all is removed: it shows nothing and the save writes nothing for it.
- **Anything else.** `marked` has corners no writing reaches — a code span holding a backtick, or a `<` with a `>` later in the block, hides the emphasis delimiters after it — so text a paste, a deletion or typing leaves where no writing of it reads back as shown shows as its save reads, as a reload of the document would show it.

## Formatting

There is no built-in toolbar in v1. Formatting is invoked four ways, all provided by Lexical (the right-click menu is this component's own addition):

- **Markdown-shortcut typing** — `# ` → heading, `**b**` → bold, `- ` → bullet, `1. ` → numbered, `> ` → quote, ` ``` ` → code block, `---`, `***` or `___` then a space or Enter → a horizontal rule, `[ ] `, `[x] ` or `[X] ` at the start of a list item's text → a task item, applied as you type. The block shortcuts (`# `, `- `, `1. `, `> `, ` ``` `, and the horizontal rule's `---`) apply at the start of a paragraph at the top level, in a `:::` column, in a quote at any depth, and in a list item's further paragraphs (the rule's shortcut applies only to a paragraph that holds nothing but the marker, and not in a heading, a list item's first line or a table cell); in a list item's first line only the inline ones apply, and the task item's shortcut applies there alone, on typing and never on Enter. A shortcut is applied by typing only — a key, text composed with an input method, an autocorrection. Deleting, cutting, pasting or dropping text applies none, whatever the text before the caret then reads as. Known limit: a composition that is cancelled or emptied right behind shortcut-shaped text still applies it. One undo takes a shortcut back and leaves the characters as typed.
- **Keyboard shortcuts** — `Ctrl/Cmd+B` (bold), `Ctrl/Cmd+I` (italic), `Ctrl/Cmd+U` (underline), `Ctrl/Cmd+Z` / `+Y` (undo/redo), `Ctrl/Cmd+Enter` (toggle the checkboxes of the task items the selection touches: all checked when any is unchecked, else all unchecked; one undo step), and a click on a task item's checkbox toggles it (refused while the editor is [read-only](#read-only)). A format shortcut declines wherever the matching toggle does (`canFormat` is `false`); at a caret it leaves the format pending for the text typed next, where the toggle formats the word.
- **Command API** — thin imperative methods you can wire to your own [`Button`](/components/Button)s to build a toolbar.
- **Right-click context menu** — a self-wired menu on the WYSIWYG surface whose contents depend on what was clicked: a word or selection gets inline-format and block-style commands, plus an **Alignment** submenu (Left/Center/Right/Justify/Default) applying `setBlockAlignment` and a **Columns** submenu (fixed 2/3/4-column presets and None) applying `setColumnCount` — so the column count can be changed from inside a populated column, not just from an empty line; an empty line gets a **Heading** submenu (h1–h6), an **Insert** submenu bundling **Quote**, **Code block**, **Bulleted list**, **Numbered list**, **Task list**, **Table** (a 2×3 starter table), an **Image…** item prompting for a source URL and applying it through `insertImage`, and a **Horizontal rule** item applying `insertHorizontalRule`, and the same **Columns** submenu; a table cell gets the same inline-format commands (no block style — a cell holds inline text only) plus a **Table** submenu bundling an **Insert** submenu (row above/below, column left/right), a **Delete** submenu (row, column, or the whole table), **Merge cells** (over a drag-selected range of cells), **Unmerge cell**, **Column width…** (prompts for a pixel width via a dialog, applying it through `setTableColumnWidth`), and an **Align column** submenu offering Left, Center, Right, and None — the four alignments a GFM delimiter row can express — with a checkmark on the column's current choice; alignment is a whole-column property, so choosing one re-aligns every cell of that column, header included, not just the clicked cell. The inline-format toggles are **Bold**, **Italic**, **Underline**, **Strikethrough**, and **Code**, and a word/selection or a table cell also gets a **Text style** submenu with **Colour** / **Font** / **Size** sub-submenus, each a fixed preset list plus a **Default** radio row that clears the override. Each preset is a radio row showing the current value (**Default** when the text carries none, nothing when it carries a value no preset has, **Default** for a selection whose parts differ); picking one applies it and leaves the menu open, so several can be tried on the same word, and each pick is one undo step. A word/selection or a table cell also offers **Insert link…** (dimmed where there is nothing to link: no selected text or image, and no word under the caret) when the click is not inside a link, or **Edit link…** / **Remove link** when it is — Insert/Edit prompt for a URL via a dialog, applying it through `toggleLink`; Remove unwraps the whole link via `removeLink()` regardless of how much of it is selected. Clicking inside a blockquote, a list, a fenced code block, or a table cell additionally shows **Insert line before block** / **Insert line after block**, which add an empty paragraph immediately outside the whole enclosing block (for a list, outside the entire list, not just the clicked item; for a table cell, outside the whole enclosing table, not just the clicked cell) and move the caret into it; a plain paragraph or a heading never show these two items. Every context leads with **Cut / Copy / Paste**; Cut and Copy are dimmed unless there is text to act on — a real selection, or (a collapsed caret) the enclosing word a format toggle, Cut, or Copy would expand into — and Paste is always enabled. Right-clicking never selects anything on its own: a collapsed caret inside a word stays a plain blinking caret while the menu is open. Choosing a format toggle, Cut, or Copy is what expands it to the whole word (visibly selecting it, so a follow-up action in the same still-open menu sees the same wider selection); Paste always acts on whatever is currently selected, so pasting right after opening the menu — before anything else — lands at the original caret, splitting the word rather than replacing it, while pasting after a format toggle (or Cut/Copy) replaces the word that toggle just selected. No consumer wiring needed — right-clicking the surface shows it directly. The menu opens below the text its items act on — the selection, the word or formatted run under the caret, or the caret's line — and above it when the room below is short, staying level with the pointer horizontally, so the text stays visible while a format or style is picked; for a selection taller than five heights of the pointer's line (three lines at the default line height) or a third of the window it keeps clear only the line under the pointer, and its submenus stay on the same side. A selection small enough to keep clear whole is kept clear whole wherever the pointer is; with the pointer on an image in a larger selection, the image's line (the image and the text beside it) is kept clear. When neither side of the text has room for the menu, the menu opens at the pointer instead, and may cover the text. A table selection, a selected image or rule, or no selection opens the menu at the pointer. Shift+F10 or the ContextMenu key opens the same menu for wherever the caret or selection is, positioned under the caret's text, the same way. A right-click that moves the caret (on Linux and macOS the browser moves it before the menu opens) gets the menu for the caret's new place: its checkmarks, its Cut/Copy state and its dimmed items all describe what the items will act on. While table cells are selected a right-click leaves that selection in place, wherever it lands, and the items go on acting on the cells, so the menu is the table-cell one even for a click outside the table. An item whose command would do nothing at the selection is dimmed: the format toggles, Text style and Insert/Edit link in a raw Markdown block, a code block or over text kept as Markdown source; the format toggles and Text style also for a selection that holds no text (from the end of one line to the start of the next, or over an image alone), and Insert link… where there is nothing a link could hold; the Insert submenu's Table and Image… when the selection touches a raw Markdown block or a code block, and Table also when the selection lies inside a table; Text style inside a link; Edit link… and Remove link in an autolink nested in another link; Block style, Heading and the list and block conversions when the selection reaches into a table cell; **Clear formatting** where the selected text carries no format; and the two **Insert line** items when the selection is anchored outside the block that was clicked. While table cells are selected the format toggles apply to the cells that can take them, and everything else that needs a text selection is dimmed — Text style, the link items, Clear formatting, the Insert line items, and in the **Table** submenu every entry but **Merge cells**, which in turn is dimmed unless more than one cell is selected; **Unmerge cell** is dimmed outside a merged cell. With no selection at all every item that acts on one is dimmed, **Alignment** and **Columns** included. Paste is never dimmed, because it always has somewhere to paste: while table cells are selected into those cells, starting at the cell the selection began in, as Ctrl/Cmd+V does; with no selection at the document's end. In a read-only editor the menu offers only Copy.

### Command API

| Method | Effect on the current selection |
| --- | --- |
| `toggleBold()` / `toggleItalic()` / `toggleInlineCode()` / `toggleStrikethrough()` / `toggleUnderline()` | Toggle the inline format. |
| `setTextColor(color)` / `setFontFamily(family)` / `setFontSize(size)` | Set (or, with `null`, clear) the selection's text colour / font family / font size. No-op inside a link, in either mode. |
| `clearFormatting()` | Clear every inline text format (bold, italic, strikethrough, underline, inline code, …), leaving plain text. Does not clear a colour/font/size override — use the matching setter with `null` for that. Block type is untouched. |
| `toggleUnorderedList()` / `toggleOrderedList()` | Convert the selected blocks into a bulleted / numbered list, or out of one. When every selected block is the text (or the heading) an item of a list of that kind opens with, those items leave the list: each becomes a paragraph, the blocks its item holds up to its first nested list follow it, and the list is split around them; the nested list's items stay in a list where the item's outermost list stood, in the item's place and as siblings (a nested item lifted out of every list sends its own nested items to that level, not under its parent). Otherwise each other selected block becomes an item of such a list where the block stands: at the top level, in its `:::` column or in its quote: an item of a list of the other kind changes alone, its list split around it, and keeps the blocks it holds up to its first nested list — select a whole list to convert it whole — and a new item joins a list of that kind right before or after it — the joined list is tight when the lists it joins are tight and the new item holds its text alone, and loose when one of them is loose or the item holds further blocks. A block a list item holds after its text becomes an item of its own, with the blocks after it. A task item's checkbox stays a checkbox while its item stays an item, and becomes the text it shows (`[x] `) when the item's text leaves its list. |
| `toggleTaskList()` | Make the selected blocks task items, or take their checkboxes off. When every selected block is the text of a task item, their checkboxes are removed and the items stay. Otherwise each selected block that opens no list item becomes an item of a bulleted list where it stands, as `toggleUnorderedList` makes one, and every selected item without a checkbox gets an unchecked one; a heading that opens an item becomes the item's text. A block with no text (an empty item or paragraph) becomes a task item that keeps its checkbox, the caret after it: the save is `- [ ]` (`- \[x\]` when checked), which a reload reads as the text `[ ]`, and a toggle off takes such a checkbox away and leaves no text. A list keeps its kind: a numbered item stays numbered, and a list can hold task items and plain ones together. One undo step. |
| `toggleLink(url)` | Wrap the selection in a link to `url` (a collapsed caret first expands to its enclosing word; with no word under it and outside a link, the call does nothing), or unwrap it when `url` is `null`. Updates the URL in place, rather than double-wrapping, when the selection already sits inside one existing link. |
| `removeLink()` | Remove the link enclosing the current selection, unwrapping it back to plain text — the whole link, regardless of how much of it (if any) is selected. |
| `setBlockType(type)` | Convert the selected blocks to `"paragraph"`, `"h1"`–`"h6"` or `"code"`, in place — in a quote too —, or, with `"quote"`, put them into a quote or take them out of it: when every selected block stands in a quote, the blocks leave their nearest quote, one level out, the quote split around them; otherwise every selected block that stands in no quote goes into one, joining a quote right before or after it. A list item's text is taken out of its lists first, and the blocks the item holds up to its first nested list follow it out of the list, and the nested list's items stay in a list where the item's outermost list stood, in the item's place and as siblings (a nested item lifted out of every list sends its own nested items to that level, not under its parent); when the item's text is put into a quote, those blocks stay outside the quote, after it. A task item's checkbox stays as the text it shows, and in a code block as it was written. |
| `insertTable(rows, columns)` | Insert a table at the caret; the first row is the header row. Without a text selection it goes in at the document's end; with a horizontal rule selected, directly after the rule, in the rule's own parent. No-op where it would land inside another table: with the selection inside one, or, without a text selection, with the document ending in one. A selection that runs from outside a table into one of its cells is removed first, that table included, and the new table goes in where it started. The block holding the caret is split only where the caret is inside its content, so no empty quote, heading or list item is left beside the table; in a quote the table goes into the quote, the block split around it; a list item is not split between its text and its nested list: the block goes into the item, in front of that list; a table that ends its container is followed by an empty line. |
| `insertHorizontalRule()` | Insert a horizontal rule at the caret, written `---`. Without a text selection it goes in at the document's end. No-op where `insertTable` is: with the selection touching a raw Markdown block or a code block, or inside a table (for the no-selection case, with the document ending in one). A range is removed first, as a typed character would; with a rule selected the new rule goes right after it, in the rule's own parent. The block holding the caret is split only where the caret is inside its content, so no empty quote, heading or list item is left beside the rule; in a quote the rule goes into the quote, the block split around it; a list item is not split between its text and its nested list: the block goes into the item, in front of that list; a rule that ends its container is followed by an empty line, and the caret lands at the start of the block after the rule. |
| `insertParagraphBeforeBlock()` / `insertParagraphAfterBlock()` | Insert an empty paragraph immediately before/after the blockquote, list, fenced code block, or table enclosing the caret, and move the caret into it. For a list or a table cell, this is the whole list or table, not just the caret's item or cell. |
| `insertTableRow(after?)` / `deleteTableRow()` | Insert a row after (default) or before the current row, or delete it. |
| `insertTableColumn(after?)` / `deleteTableColumn()` | Insert a column after (default) or before the current column, or delete it. |
| `setTableColumnAlignment(alignment)` | Set the alignment (`"left"` / `"center"` / `"right"` / `"none"`) of the column holding the caret, on every cell in that column. |
| `deleteTable()` | Delete the entire table containing the caret, including every row and cell. |
| `mergeTableCells()` | Merge the cells of the current drag-selected range into one. The merged cell holds the text of each merged cell on a line of its own, saved with the cell break (see [Markdown](/components/Markdown#supported-syntax)); an empty first cell adds no blank line, and the caret lands in the merged cell. No-op unless the selection spans more than one cell, and header cells do not merge: Markdown merges body cells only. |
| `unmergeTableCell()` | Split the merged cell containing the caret back into its individual cells. |
| `setTableColumnWidth(width)` | Set (or, with `null`, clear) the width in pixels of the column the caret sits in. |
| `setBlockAlignment(align)` | Set (or, with `null`, clear) the block alignment of the top-level blocks the selection spans, wrapping (or unwrapping) a `:::` fence as needed. A fence whose opening line carries the author's own words (`::: tip Title`) is never unwrapped. |
| `setColumnCount(count, gap?)` | Grow or shrink the number of explicit column regions in the block the selection sits in (or wrap the top-level blocks the selection spans in a new one), and optionally set the column gap. Growing appends empty columns; shrinking merges the surplus columns' content into the last column kept, except a column left exactly as this method created it (a single empty paragraph), which is dropped instead. `count` is clamped to 1–6; `null` means one column. Unwraps the fence when the result carries no alignment and no more than one column. A fence whose opening line carries the author's own words (`::: tip Title`) is never unwrapped. |
| `insertImage(src, options?)` | Insert a sized, validated image at the caret. `options` may set `alt`, `title`, `width`, and `height`. Without a text selection it goes in at the document's end. No-op when `src` is empty or fails the scheme allow-list. With a horizontal rule selected the image goes in a paragraph of its own right after it. |
| `cut()` / `copy()` | Write the selected text to the system clipboard; `cut()` also removes it. A selection that runs from outside a table into one of its cells is cut or copied with the whole table (see *Tables* above). `cut()` is refused while the editor is [read-only](#read-only): nothing is copied or removed. Ctrl/Cmd+X on the WYSIWYG surface is refused the same way. |
| `paste()` | Read the system clipboard and insert it at the caret, replacing any selection. With table cells selected the text goes into the cells, starting at the one the selection began in, as Ctrl/Cmd+V puts it; with no selection it goes in at the document's end. Async: resolves `true` when the clipboard was read, `false` when the browser would not allow the read. Refused while the editor is [read-only](#read-only): it resolves `false` without reading the clipboard. |

Each command operates on the current selection and no-ops (without throwing) when there is no selection, except `insertTable`, `insertHorizontalRule`, `insertImage` and `paste`, which then insert at the document's end. The format toggles, the colour/font/size setters and `toggleLink` also no-op when their result could not be saved as it shows — see [What Markdown cannot hold](#what-markdown-cannot-hold). The format toggles, the colour/font/size setters, `toggleLink`, `insertTable`, `insertHorizontalRule` and `insertImage` also no-op when the selection touches a raw Markdown block or a code block (for the three inserts without a text selection: when the document ends in one), and the toggles, setters and `toggleLink` when it holds an atomic run kept as source (see [Kept as source](#kept-as-source)). With whole table cells selected, a format toggle works cell by cell under the same rules: a cell holding such a run, or whose result could not be saved as it shows, is left as it is, as is a cell with no text (an empty one, or one holding an image alone), and the rest take the format, which comes off when all the text in the cells taking it already has it. `setBlockType` and the three list toggles no-op when the selection touches a table cell — whole cells selected included — which holds text only — a heading or list made there would be saved into the cell as its literal syntax. A list next to a raw list block is saved with another bullet or delimiter when its own would make the viewer join the two lists. The row/column/table commands additionally no-op when the caret is not inside a table cell, and for a selection that starts in a cell and runs out of its table; `mergeTableCells` needs more than one cell selected instead. A command that applies takes keyboard focus to the editor before it acts, so a toolbar or menu click leaves the keyboard in the editor, with table cells still selected; `setValue` and `setMode` leave keyboard focus where it is, and a host that wants the caret in the editor after a load calls `focus()`. `insertParagraphBeforeBlock`/`insertParagraphAfterBlock` no-op when the caret is not inside a blockquote, list, fenced code block, or table cell. A command declined for any of these reasons changes nothing: the document, its selection and the undo history stay as they were, and neither `"change"` nor `"selectionstate"` fires.

Enter in a task item opens an unchecked one (`- [x] two` split after `t` is `- [x] t` and `- [ ] wo`), and Enter on one with no text ends the list, a nested one moving out a level and staying a task item, while one that holds a further paragraph stays, the caret moving into the paragraph and the checkbox staying (the save is `- [ ]`, which a reload reads as the text `[ ]`); Backspace right after a checkbox removes it, and a second Backspace does what it does in a plain item. A caret before a checkbox, which a click left of it or ArrowLeft from the start of the item's text can make, acts as the caret right after it for typing, a paste, Enter, Backspace and a composition.

`paste()` depends on the browser granting a clipboard-read permission, which some browsers prompt for and some refuse outright for page scripts; a refused or unavailable read resolves `false` rather than throwing. The context menu's own Paste item shows a toast asking the user to press Ctrl/Cmd+V instead when this happens — `paste()` itself stays silent, so a consumer wiring their own Paste button can show their own message.

In `"source"` mode, `cut`/`copy`/`paste` go to the source editor, and these run the WYSIWYG command on the Markdown around the selection: the five format toggles, `toggleLink`/`removeLink`, `clearFormatting`, `setTextColor`/`setFontFamily`/`setFontSize`, `insertImage`, `setBlockType` and `toggleUnorderedList`/`toggleOrderedList`/`toggleTaskList`; `insertTable`, `insertHorizontalRule` and `insertParagraphBeforeBlock`/`insertParagraphAfterBlock` edit the raw Markdown directly. The other eleven — `setBlockAlignment`, `setColumnCount`, and the nine table-structure commands (`insertTableRow`/`deleteTableRow`, `insertTableColumn`/`deleteTableColumn`, `setTableColumnAlignment`, `deleteTable`, `mergeTableCells`, `unmergeTableCell`, `setTableColumnWidth`) — stay WYSIWYG-only and no-op in `"source"` mode.

## Live selection state

`getSelectionState()` returns a snapshot of what the caret currently sits
in — the five inline-format flags (`bold`/`italic`/`strikethrough`/`code`/`underline`),
whether there's a selection to act on, the URL of an enclosing link (if any),
which commands would apply there (the twelve `can…` fields),
whether it's inside a table cell and that column's alignment, and the
enclosing `:::` block's alignment and column count — and `on('selectionstate', fn)`
fires whenever that snapshot changes, for building a toolbar whose buttons
press, enable, or check themselves to match the caret's position (as
[`MarkdownDocumentPanel`](/components/MarkdownDocumentPanel)'s own toolbar
does):

```typescript
editor.on('selectionstate', (state) => {
    boldButton.setSelected(state.bold);
    tableButton.setEnabled(state.canEditTable || state.canMergeCells || state.canUnmergeCell);
});
```

The event does not fire for the editor's initial position, whichever
surface it starts on, so a toolbar seeds itself by calling
`getSelectionState()` once when it wires the listener; the one exception is
the build-time correction of the three insert fields described below. It fires on every editor commit whose resulting state differs
from the last one reported — including a same-position format toggle
(clicking a format button doesn't move the caret, but still changes what
it reports), not just a caret move. Outside a table, `tableColumnAlignment`
is `null`, as it is, with `inTable` `false`, while whole table cells are
selected and for a selection that starts in
a cell and runs out of its table; outside a `:::` block, `blockAlignment` is `null` and
`columnCount` is `1`. `inTable` says where a caret or a text selection is, not what
applies there: a control that runs a table command reads the three table
fields below. The five format flags describe the text a format toggle would act on, read from that text however the selection was made — with the mouse, the keyboard or from code. At a caret in a word they are the word's formats. Over a selection a format is on when every selected character carries it; for bold, italic and strikethrough the edge whitespace they never stay on is left out. At a caret with no word under it they are the formats pending for the text typed next.

Twelve fields report whether a group of commands would apply at the
selection, so a toolbar can grey out what would do nothing. Each command
declines on its own field before it touches anything, so a field that is
`false` means the command changes neither the document nor the selection:

| Field | Commands | `false` when |
|---|---|---|
| `canFormat` | the five format toggles | there is no selection; the selection touches a raw Markdown block or a code block; it holds text kept as Markdown source; it is not collapsed and holds no text (from the end of one block to the start of the next, or over an image alone); table cells are selected and none of them holds text free of such source |
| `canStyle` | `setTextColor` / `setFontFamily` / `setFontSize` | there is no selection; the selection touches a raw Markdown block or a code block, or holds text kept as Markdown source; it is not collapsed and holds no text; the caret is inside a link; table cells are selected |
| `canLink` | `toggleLink(url)` | there is no selection; the selection touches a raw Markdown block or a code block, or holds text kept as Markdown source; either end of it is in an autolink nested in another link; there is nothing a link could hold (a caret with no word under it and outside a link, or a selection holding neither text nor an image); table cells are selected |
| `canRemoveLink` | `removeLink()` | the selection is not inside a link, or that link is an autolink nested in another link; there is no selection; table cells are selected |
| `canSetBlockType` | `setBlockType`, `toggleUnorderedList`, `toggleOrderedList`, `toggleTaskList` | there is no selection; table cells are selected; the selection reaches into a table cell, or stands on a table and holds no block of text |
| `canSetBlockLayout` | `setBlockAlignment`, `setColumnCount` | there is no selection; table cells are selected |
| `canInsertTable` | `insertTable` | the selection touches a raw Markdown block or a code block; it lies inside one table; without a text selection (none, or table cells selected), the document ends in a raw Markdown block, a code block or a table |
| `canInsertImage` | `insertImage` | the selection touches a raw Markdown block or a code block; without a text selection (none, or table cells selected), the document ends in one |
| `canInsertHorizontalRule` | `insertHorizontalRule` | as `canInsertTable`: the selection touches a raw Markdown block or a code block; it lies inside one table; without a text selection (none, or table cells selected), the document ends in a raw Markdown block, a code block or a table |
| `canEditTable` | `insertTableRow` / `deleteTableRow`, `insertTableColumn` / `deleteTableColumn`, `setTableColumnAlignment`, `setTableColumnWidth`, `deleteTable` | the caret is not in a table cell; table cells are selected; the selection starts in a cell and runs out of its table |
| `canMergeCells` | `mergeTableCells` | fewer than two table cells are selected; a header cell is among them |
| `canUnmergeCell` | `unmergeTableCell` | `canEditTable` is `false`; the caret's cell spans one row and one column |

`canInsertTable` is `true` for a selection that runs from outside a table
into one of its cells, whichever way it was made: `insertTable` removes that
selection first, its table included, so the new table does not land in a
cell. While a horizontal rule is selected `canInsertTable`, `canInsertImage` and
`canInsertHorizontalRule` are `true`, since each insert then puts its block
right after the rule, in the rule's own parent (the document, a list item, a
quote or a `:::` column), never inside the block that follows it; the
selection state also reports `hasSelectedText` while one is. A caret links the word it is in, as the format toggles format it, and
re-points a link it is inside; `canLink` is `false` at a caret with neither.
A Link control is enabled on `canLink`, or on `canRemoveLink` for its Remove
action, as `MarkdownDocumentPanel`'s is. A Table control is
enabled on `canEditTable || canMergeCells || canUnmergeCell`, so its Merge
cells entry is reached with cells selected, and dims each entry on its own
field. A caret takes a format or a style as pending, for the text typed
next, which is why `canFormat` and `canStyle` are `true` at a caret in an
empty block. The fields follow the rules a command declines on up front; a
format, style or link that turns out not to be writable as Markdown is still
declined when tried, and then leaves the document, the selection and the
undo history as they were (see
[What Markdown cannot hold](#what-markdown-cannot-hold)). A field covers a
command, not a call. Where the argument asks for what is already there —
`setBlockType("paragraph")` in a paragraph, `setTableColumnAlignment` or
`setTableColumnWidth` with the value the column has, `setBlockAlignment` or
`setColumnCount` with what the `:::` block has, or with nothing to clear
outside one — the field is `true` and the call changes nothing, as a
declined one does: no block is replaced, no undo step is added and no event
fires.

Before the editor has a selection — a freshly built editor nobody has
clicked into — every field but the three inserts is `false`: those commands
act on a selection. The three inserts make a caret of their own
at the document's end, as they also do while table cells are selected, so
they follow how the document ends: `false` where the insert would land in a
block that declines it. Until the Lexical editor is built — on the WYSIWYG
surface's first layout, or by the first command — all report `true`, and
`"selectionstate"` fires once when the build finds any of them `false`. In
`"source"` mode, where a command declines depends on the raw text around the
selection and is not predicted: the fields are `true`, except
`canRemoveLink`, which is `true` only inside a link, and
`canSetBlockLayout` and the three table fields, which are `false` because
the alignment, column and table commands are no-ops there. In a
[read-only](#read-only) editor all twelve are `false`, on either surface;
`inTable` still says where a caret or a text selection is.

In `"source"` mode the five format flags, `hasSelectedText`, and `linkUrl`
are derived from the raw Markdown around the caret, read with the viewer's
parser — a flag is set while the selection lies inside that format (a
`**…**` or `__…__` run for `bold`), and `linkUrl` is the target of a link of
any form around it; `inTable` is always
`false`, `tableColumnAlignment` and `blockAlignment` are always `null`, and
`columnCount` is always `1` — the fields a Lexical-only construct has no
raw-text equivalent for. `setMode` emits a fresh state for the surface it
switches to, once that surface is the one showing, so a toolbar never keeps
the outgoing surface's last-reported state after a switch. `setValue`
reports the state of the document it loads; the first one on an editor not
built yet does not report the document it replaces.

A source-mode format flag is set whenever a run of that format encloses the
selection, however far out it sits — `bar` in `**foo, **bar** az**` reports
`bold` — and pressing that format's toggle then does what it does on the
WYSIWYG surface.

## Common methods

| Method | Purpose |
| --- | --- |
| `getValue()` / `setValue(value)` | Read or replace the whole document as a Markdown string. |
| `getMode()` / `setMode(mode)` | Read or switch the editing surface — see [Source / WYSIWYG mode](#source-wysiwyg-mode). |
| `getReadOnly()` / `setReadOnly(readOnly)` | Read or toggle whether the editor accepts edits. |
| `on('change', fn)` / `off('change', fn)` | Subscribe to content changes (the payload carries the new Markdown). |
| `getSelectionState()` | Read the caret's current tracked state — see [Live selection state](#live-selection-state). |
| `on('selectionstate', fn)` / `off('selectionstate', fn)` | Subscribe to changes in that state. |
| `on('readonlyedit', fn)` / `off('readonlyedit', fn)` | Subscribe to edits refused because the editor is read-only — see [Read-only](#read-only). |
| `dispose()` | Detach the Lexical registrations and the editor root — call before discarding a dynamically-built `MarkdownEditor`. |
| `markClean()` | Clear the dirty flag, accepting the current document as the clean baseline. |

Saving changes only what was edited. A top-level block you did not touch — a paragraph, list, table, quote or fence — is written back exactly as it was loaded, with the blank lines around it. In an edited list, table, fenced code block, `:::` fence or quote, the items, rows, cells, fence lines, column blocks and quoted blocks you did not touch are written as they were too, and only what you edited is written in the editor's standard form (see [Supported constructs](#supported-constructs): `*` emphasis, `#` headings, fenced code, …). An unedited part is written again in the standard form where its text would read otherwise in its new place: an item whose list now writes another marker, or turns tight while the item holds a blank line, an ordered item whose new number has more or fewer digits than the number it was written with (a number written with leading zeros is kept while its number is unchanged), a list item or table row moved into or out of a `:::` column, a table cell that holds `^^` or `<<` as text, since next to other rows or cells it would merge them, a fence whose code now holds a line that would close it, a block of a quote moved out of it (its new container writes it), and — once a link reference definition is edited — a part holding a `[`. The lines of an edited block of a quote take `> ` before each line, and the lines between it and an unedited neighbour take `>`. An unedited ordered item whose number changes keeps its text and gets its new number in place of the old one. Any other edited block is written in the standard form. An unedited document, and a switch to source mode and back, return the text unchanged except that `\r\n` line endings become `\n`. Undo keeps this: undoing past a `setValue` or a switch back from source mode returns the earlier document's untouched blocks as written. An untouched block is also written in the standard form where its text would read differently in its new place: an indented block that now follows a list, an unclosed code fence that something now follows, a paragraph opening a `[` it does not close where text now written after it would close it into a link reference definition (`marked` reads a definition's label across blank lines), and — once a link reference definition is edited — a block whose bracketed text the new definitions read differently (text that becomes a link, or a link whose URL changes); every other block keeps its source.

## Source / WYSIWYG mode

The editor has two surfaces, selected by its `mode`:

- `"wysiwyg"` (default) — the Lexical rich-text surface described above.
- `"source"` — a raw-Markdown [`CodeEditor`](/components/CodeEditor), for editing the Markdown text directly.

Both surfaces are bound to the **same Markdown value**, so `getValue()` / `setValue()` and the `"change"` event behave identically whichever mode is active, and switching modes **preserves the document** (the text is converted across on each switch). `setReadOnly` applies to both surfaces. In `"source"` mode, HTML is typed literally, with no close tags added, and Enter in a code block or in HTML keeps the new line in the blockquote or list item it was pressed in; see [CodeEditor's built-in languages](/components/CodeEditor#built-in-languages). The source surface keeps the Markdown's content in the text colour and gives each kind of syntax a readable colour of its own, with no bold, italic or underline; the same section lists the kinds and their colours.

```typescript
const editor = new MarkdownEditor('# Title', { mode: 'source' });

editor.getMode();            // "source"
editor.setMode('wysiwyg');   // convert the source text into rich text and show it
editor.getValue();           // same Markdown, regardless of the active mode
```

Like the [command API](#command-api), the mode toggle is **consumer-wired** — the editor ships no built-in chrome. Drive `setMode` from your own control (e.g. a [`ToggleButton`](/components/ToggleButton)) when you want to expose the switch to users.

Source mode runs the WYSIWYG command for the commands listed at the end of the [command API](#command-api): it reads the Markdown around the selection — the top-level blocks the selection touches and one on each side, with the document's link reference definitions — into the editor's own document, runs the command there as on the WYSIWYG surface, and writes back only the text that changed, leaving the selection where the WYSIWYG command leaves it. The result is the document the WYSIWYG command saves for the same selection, and the command is one undo step of the source editor.

Two things follow. A command writes the list item, table row or cell, or block it changes in the form the editor saves — `__bold__` as `**bold**`, a tab in the indentation as spaces, a character reference as its character where the save needs no reference — as a WYSIWYG edit does; the items, rows and blocks around it stay as written. And a command does nothing where the WYSIWYG surface holds the text as a raw Markdown block (see [Kept as source](#kept-as-source)): the WYSIWYG command would write that block's text escaped (`- \> - one`). A quote is a raw block there only when it is one on the WYSIWYG surface (see [Kept as source](#kept-as-source)). A command also does nothing with the caret on a blank line between blocks (between top-level blocks, or between the blocks of a list, a list item, a quote or a `:::` column, as in `- a`, a blank line, `- b`; a range end there goes on to the block beside the container when the container has no block on that side), on a `:::` fence's opening, `|||` and closing lines and on a table's delimiter row, which name no block either, and where the editor does not find the source of what a block shows beside the selection: an HTML line whose container prefix holds a tab, a code line holding a tab that `marked` reads into a quote CommonMark ends there, a paragraph line made of list markers and tabs, a task item's checkbox followed by more than one space in a list with blank lines between its items, and a list item's text that begins as a link reference definition repeated before it. A caret in a block that shows nothing (an empty heading, item, quote or code block, or a text of blank lines alone) acts as in the WYSIWYG editor when the block holds one empty place (`-` is one empty item), and does nothing when it holds several (three empty items on three lines: each line names its item, but the editor does not work out which yet); a caret on the empty lines after the last block, where no block ends open, acts on a new block there; a block the import builds whole and the editor then splits (a quote followed by a lazy HTML line) is placed only when it is the only block the command imports.

`insertTable`, `insertHorizontalRule` and the paragraph commands edit the raw text directly: `insertTable` and `insertHorizontalRule` go above the whole block holding the caret — a paragraph, an HTML block or a table, never inside one — and the paragraph commands step out of the top-level quote, list, table or code block around the caret. On a blank line inside a list or a quote, `insertTable` and `insertHorizontalRule` do nothing, since a table or a rule there would split the list or quote. After `insertHorizontalRule` the caret keeps its character: the selection moves down by the lines inserted. A caret on a horizontal rule's line selects the rule, as a click on it does, so a command there does nothing but an insert, which goes after the rule; a range that has rule lines at its ends is acted on as any other.

The editor reads a tab as the viewer does (see [Tabs](/components/Markdown#tabs)). It writes indentation as spaces, so a block that is written again after an edit loses the tabs of its indentation and keeps every tab inside its text, its code spans, its code blocks and its HTML; an edited block whose source holds a tab is written in the standard form whole, without keeping its unedited items or rows. A block that was not edited is saved byte for byte, tabs included. A code line inside a list item or a quote keeps a tab its container leaves whole, as the viewer reads it, so an edit elsewhere in the item saves that tab where it was; a tab the container cuts across is saved as the spaces it reads as. A raw Markdown block, an HTML block or a quote or list the editor keeps as one, shows and saves its text as written, tabs included, also inside a list item written in the standard form (its marker at the margin and one space after it); in an item written otherwise it shows the spaces its tabs stand for.

## Dirty state

The editor reports itself dirty, via [`Component.isDirty()`](/api/core/classes/Component), whenever `getValue()` differs from the Markdown at the last clean point — the clean point is the value it was constructed with, or the value `markClean()` last accepted. Both surfaces go through the same check, so an edit undone back to the clean text clears the flag on its own, and a mode switch that changes nothing textually does not set it. `isDirty()` folds up into every ancestor container automatically. A host that loads a document with `setValue()` should follow it with `markClean()`, so the loaded text becomes the clean text.

## Read-only

`setReadOnly(true)` locks the editor against edits; `false` lifts the lock. A read-only editor keeps its caret, on both surfaces:

- It is a tab stop. Tab and Shift+Tab leave it, from a table cell too.
- The arrow keys, Home and End, PageUp and PageDown, and their word and document forms move the caret. Shift with any of them selects, and Ctrl/Cmd+A selects the editor's text, not the page's. The mouse selects as before.
- Ctrl/Cmd+C copies the selection. Shift+F10 or the ContextMenu key opens the context menu at the caret, which then offers only Copy.
- Enter with the caret in a link opens the link, and so does a click on one — see [below](#following-a-link).
- A task item's checkbox is drawn with `aria-readonly="true"` and the default cursor while the editor is read-only, and a click on it is refused (see below).
- Switching read-only on or off leaves the selection and the keyboard focus where they are.

While read-only no edit reaches the document or the undo history, and a refused edit leaves the caret or the selection where it is:

- Typing, Enter outside a link, Backspace and Delete, a click on a task item's checkbox and Ctrl/Cmd+Enter on one, `toggleTaskList`, a paste, a cut, a drop, a composition (IME input), a spelling replacement, and the browser's format shortcuts (Ctrl/Cmd+B, +I, +U) are refused. Text that is dragged out of the editor is copied, not moved.
- The undo and redo keys (Ctrl/Cmd+Z, Ctrl+Y, Ctrl/Cmd+Shift+Z, and Alt+Backspace with or without Shift, which a browser on Windows gives its undo and redo) do nothing: not in the editor, whose history is kept as it is for when the lock is lifted, and not in the rest of the page, whose last edit the browser's own undo would otherwise take back from here.
- Every command that edits is refused, called from code or from a toolbar: a call such as `toggleBold()`, `insertTable()`, `insertHorizontalRule()` or `cut()` leaves the document and the selection as they are, and `paste()` resolves `false` without reading the clipboard. `copy()` still copies.
- Replacing the whole document with `setValue()` stays possible, as on a read-only `CodeEditor`: read-only guards against edits, not against the host loading another document. To change a read-only editor's document from code, load the new text with `setValue()`, or lift the lock around the command.

A refused edit fires `"readonlyedit"` and flashes the surface it was made on, with the brief error-coloured wash a read-only `CodeEditor` plays. In WYSIWYG mode the event fires once for each edit the surface refuses, for each editing command called on the editor, and once for each step of a composition, when the browser announces the text it is about to write. A composition that starts with no text to write, as an on-screen keyboard starts one around the word a tap puts the caret in, is no edit and is not reported. Two kinds of key are not reported there: Tab, which moves the focus on, and the undo and redo keys, which are stopped quietly. In `"source"` mode the event fires for what the source editor reports, which [CodeEditor's Read-only section](/components/CodeEditor#read-only) lists; there too the undo and redo keys are quiet, every editing command called on the editor is refused once, as on the WYSIWYG surface, and the cut key copies the selection where the WYSIWYG surface refuses it.

```typescript
editor.on('readonlyedit', () => statusBar.setText('This document is read-only.'));
```

`getSelectionState()` reports every `can…` field `false` while read-only, and `"selectionstate"` fires when `setReadOnly` changes them, so a toolbar built on those fields greys out — as [`MarkdownDocumentPanel`](/components/MarkdownDocumentPanel)'s does, its Table button included, which reads `canEditTable`, `canMergeCells` and `canUnmergeCell`. The other fields follow the caret as it moves: `bold`, `linkUrl`, `inTable` and the rest say what the caret is in. `inTable` is not a `can…` field: it says where a caret or a text selection is (it is `false` while whole table cells are selected, and for a selection that runs out of its table), and stays `true` in a read-only editor's table cell, so a control enabled on it alone would stay enabled.

While it is `contenteditable`, the WYSIWYG surface is a multi-line text box to assistive technology: it carries `role="textbox"`, `aria-multiline="true"` and `aria-readonly`, which follows the read-only state. These are the attributes the source surface's content carries. After `setContentEditable(false)` it carries none of the three: it takes no focus and has no caret, and its headings, links, lists and tables are exposed as what they are.

What a browser makes of `aria-readonly` is the browser's. Chromium reports the text box and that it is multi-line, but reports an editing host as editable whatever `aria-readonly` says, on the WYSIWYG surface and on the source surface alike. That was measured in Chromium's accessibility tree; no screen reader was run. A screen reader user there may meet a field announced as editable that takes no typing, and nothing but the flash, which is visual, says why. `"readonlyedit"` is the hook for a host that wants to say it, in its own words, through a description or an announcement of its own.

`setContentEditable` is separate from read-only, in both directions. It decides whether the WYSIWYG surface hosts a caret at all: `setContentEditable(false)` takes the caret, the keyboard selection and the tab stop away, read-only or not. A read-only editor's surface is `contenteditable`, which is what gives it its caret, and `setContentEditable(true)` cannot make a read-only editor editable: every edit is refused all the same.

Known limits of a read-only WYSIWYG surface:

- `copy()` at a caret copies the word the caret is in without selecting it.
- Each keystroke of a refused composition is reported, since putting the view back ends the composition.
- A composition refused while whole table cells are selected leaves the cells selected, but the browser's caret is not put back where it was.
- Keyboard selection is the browser's. Shift with an arrow key selects text inside a table cell; carried past the cell's edge it selects whole cells, and the browser's own selection then no longer shows what Ctrl/Cmd+C copies.
- An open context menu is not worked with the arrow keys; Ctrl/Cmd+C is the keyboard's way to Copy.
- The surface raises an on-screen keyboard on a touch device when it takes focus, and shows the browser's spelling marks, as an editable one does.
- Text that a script or a browser extension writes straight into the surface's elements, with no input event, reaches the document as it does on an editable editor.
- So does a key's or a composition's edit where another script has a capture listener on the window, registered before the library's, that stops `beforeinput` from propagating, and a listener for `input` there too. With `beforeinput` hidden from it the editor can neither cancel the edit nor step aside for it, and the other listener's turn at `input` comes first.
- The read-only state is written as `aria-readonly`, which Chromium does not pass on to assistive technology for an editing host (see above).

The editor's other open defects, read-only or not, are listed under [Known limitations](#known-limitations).

For a purely *display* use case, prefer the leaner [`Markdown`](/components/Markdown) viewer, which needs no Lexical — `MarkdownEditor`'s read-only mode is for temporarily locking an editor, not for replacing the viewer.

### Following a link

A read-only editor follows its links; an editable one does not, since a click there places the caret for editing and Enter breaks the paragraph.

- **By keyboard:** move the caret into the link and press Enter. `getSelectionState().linkUrl` says when the caret is in one, and Enter follows the link at every place where it does: in the link's text, and beside an image the link holds. A held Enter opens the link once.
- **By mouse:** click the link, with the main button or the middle one. A run of clicks opens the link once, on its first click: the later clicks of a double click, a triple click or a longer run go on to select a word or a block and open nothing more. A first click that itself selects text, the end of a drag or a Shift+click, does not open the link. A click on a link whose text is selected already opens it, and a click beside a link does not.

The link opens in a new tab, with `target="_blank"` and `rel="noopener noreferrer"`, as a link of the [`Markdown`](/components/Markdown) viewer does by default. Its address is the one the link was written with, which is what `linkUrl` reports: a relative address, or one that starts with `http:`, `https:`, `mailto:`, `tel:` or `sms:`. A link with any other scheme, `javascript:` for instance, is not followed, and neither is a relative address that holds a `:` or a link with an empty address (`[text]()`); Enter in such a link is a refused edit like Enter anywhere else. Following a link is not an edit: no `"readonlyedit"` fires and nothing flashes.

Enter follows a link from a caret only, and pressed alone. With text selected it is a refused edit, and so is Shift+Enter; with Ctrl, Alt or Cmd held the editor does not treat it as Enter and leaves the key to the browser: it follows no link, and whatever edit the browser then announces is a refused edit like any other.

The editor alone follows a link of a read-only editor. Where the surface is not `contenteditable` (after `setContentEditable(false)`), a browser would follow a clicked or middle-clicked link itself, a click in the same tab; the editor cancels that and opens the link in a new tab as above. There a link is a tab stop of its own, and Enter on it follows it. An editable editor leaves a click on a link to the browser.

## Theming

The editing surface's class rules reference the same CSS custom-property tokens the viewer uses (`--ts-ui-font-mono` for code, `--ts-ui-border-color` for the quote bar and the line of a horizontal rule, `--ts-ui-indicator-focus` for links and for the ring of a selected rule), and a task item's checkbox is drawn with the tokens the [`Checkbox`](/components/Checkbox) component draws its box with (`--ts-ui-form-border`, `--ts-ui-checkbox-radius`, `--ts-ui-checkbox-bg`, `--ts-ui-checkbox-bg-selected` and `--ts-ui-checkbox-check-color`), so a [`ThemeManager.setTheme`](/api/core/classes/ThemeManager) toggle recolours it immediately with no rebuild, and the edited rich text visually matches what the viewer renders.

## Known limitations

These are defects that are still open. They are rare, and most need a hand-written construct or a selection that starts inside a raw Markdown block. The rules under [What Markdown cannot hold](#what-markdown-cannot-hold) are deliberate and are not repeated here, and neither are the limits of a [read-only](#read-only) editor, which that section lists, or the typing-shortcut limit under [Formatting](#formatting) (a composition that is cancelled or emptied right behind shortcut-shaped text still applies the shortcut). The editor reads Markdown with the viewer's parser, so the viewer's own [known limitations](/components/Markdown#known-limitations) show on the WYSIWYG surface too. In the examples, `·` is a space and `→` a tab.

### Saved text that can come out different

- **A line holding only an em space after a line break.** When the line after a line break holds nothing but an em space or a thin space (in `a`, a line break and `b`, select `b` and type an em space), the editor turns the break into the text `a\`, and the viewer shows `a\` with no break; in a list item a reload also drops the space, and in a table cell the save keeps the break and drops the space. A no-break space in the same place keeps both the break and the space (it is saved as `&nbsp;`).
- **A character reference for a space at a block's start.** `&#32;a` and `&#32;&#32;a` load as the paragraph `a`. The reference stays in the file while the block is not edited; once it is (`z` typed after `a`), the save is `az`. The viewer shows `a` either way, since it draws no space at a paragraph's start, so only the source loses it.
- **A no-break space after a lone checkbox's character reference.** `- [x] &#32;` followed by a no-break space loads as a checkbox alone, as the viewer shows it, and keeps the no-break space in the file while the item is not edited; once the checkbox is toggled, the save is `- [ ] &#32;` and the no-break space is gone. Nothing shown changes; only the source loses it.
- **A carriage return written as `&#13;` in a task item.** `- [x] a&#13;` saves unchanged until its checkbox is toggled; then the save holds a raw carriage return where the reference stood (`- [ ] a` and the character itself). The viewer shows the item as before, but the file holds a control character the author did not type.
- **A backslash escape joined into an HTML block.** An HTML block reads no backslash escapes, so an escaped character that a deletion joins into one shows its backslash: under an HTML block of `<div>`, `raw` and `</div>`, a paragraph `ab \*y\*` shows `ab *y*`; Delete from the end of `</div>` to after `ab` leaves the HTML block ending in `</div> \*y\*`. Type the joined text again without its backslashes.
- **A deletion from a raw Markdown block into a later block.** A range that starts in a raw Markdown block (an HTML block, or a list the editor keeps as source) and ends in a later block joins what is left of that later block as Markdown text, and the text can then read as something else. The same range started in a paragraph keeps the rest as text, and one undo takes the deletion back.
  - The rest of a later raw block can become a code block or a heading: with `<div></div>`, a blank line, `- x····y` and `··> q`, Delete from the start of `<div></div>` to after `- x` leaves a code block holding `y`.
  - The later lines of a code block's rest read as Markdown: with `<div></div>`, a blank line and a code block holding `x` and `# y`, Delete from the start of `<div></div>` to after `x` leaves the heading `y`; a line `1. y`, `> y` or `- y` becomes a list or a quote.
  - A rest that lands at the start of a raw list's line right after a quote line joins that quote: with `- a`, `··- b`, `····> q`, `··- c`, a blank line and `x→# y`, Delete from the start of `··- c` to after `x` moves `# y` into the quote, whose paragraph then reads `q # y`.
  - A `<` left open at the joint gets a backslash before the `>` that closes it even inside a code span, where the viewer shows the `>` as it is: with `` - a `<b w ``, `··> q`, a blank line and `` ab>c` d ``, Delete from after `<b` to after `ab` leaves a code span whose text the editor shows and saves as `` <b\>c\ ``, where the joined text reads `<b>c`.
- **Tabs after marker characters on a paragraph's later line.** In `- a` over `→→-→-→b c`, the tabs after the `-` characters read as the spaces that reach their tab stops (see [Tabs](/components/Markdown#tabs)), and once the item is edited (bold on `a`) the save writes them as spaces: `··\-···-···b·c`. Without the marker characters (`→→x→-→b c`) the tabs are kept. The viewer shows the same either way.
- **A rule and a paragraph pasted right after a checkbox.** With the caret at the start of a task item's text (`- [x] one`, before `one`), a paste of a horizontal rule followed by a paragraph (a web page's `<hr><p>two</p>`) turns the checkbox into the text `[x]` and puts the rule and the paragraph into the item: the save is `- \[x\]`, `··---` and `··twoone`. A rule pasted alone goes above the item, which keeps its checkbox.
- **A multi-line image with a tab, pasted into a list item.** An image whose alt text runs over two lines, the second opening with a tab (`![a` over `→# d](/i.png)`), copied from another `MarkdownEditor` and pasted into a list item's text, saves in a form that does not read back as the image: after `- q` the reload is a raw Markdown block, and in a quote or an item's later paragraph the second line reads as the heading `d](/i.png)`. The same image written with spaces saves as it shows.
- **Pasted HTML beside a form control.** A web page's `Agree <input type="checkbox"> to terms` pastes as `Agreeto terms`: the space beside an `<input>` or a `<button>` is lost in Lexical's HTML import. Type the space again.
- **Spaces the editor shows that a save drops.** The editor can show a space the saved text does not hold; the text is right, and a reload shows it without that space.
  - A blank before a soft line break: `a·` over `b` shows two spaces between `a` and `b`, where the viewer shows one.
  - Shift+Enter right after a space: in `a·b` with the caret before `b`, the editor shows `a·`, a break and `b`, and the save is `a\` over `b`.
  - The rest of a block joined by a deletion from a raw Markdown block, when it opens with a tab or four spaces or holds spaces after an image: with `<div></div>`, a blank line and `x→# y`, Delete from the start of `<div></div>` to after `x` shows `·# y` and saves `\# y`.

### Commands, caret and API

- **Source-mode commands in a quote whose later line holds only list markers.** In `> a` over `→- -` over `b` (or the same with four spaces before `- -`), the quote shows one paragraph, `a - - b`, and no source-mode command acts anywhere in the quote, since the editor finds no place there for the caret. The blocks around it act as usual, and the WYSIWYG surface edits the quote.
- **Source-mode commands among several empty items.** With the caret on one of several empty list items (`-` over `-` over `-`), on an empty body cell of a table whose cells are all empty, or in one of several empty `:::` columns, the block and insert commands do nothing in source mode: the editor does not yet work out which of them the caret's line names. With one empty item they act. Run the command on the WYSIWYG surface, or type into the item first.
- **The caret on a lone checkbox's line in source mode.** In `- [x] &#32;` over `- b`, a caret anywhere on the first line from its `[` on acts on the next item: Heading 2 there gives `## b`. Put the caret on the line's `-`, before the space ahead of `[`, or run the command on the WYSIWYG surface, and it acts on the checkbox's own item.
- **The caret after a mode switch, on a nested quote's line after a hard break.** In a quote inside a list item, `- > a\` over `··>··cd`, a source-mode caret just before the second line's `>`, just after it, or after the first space that follows it lands after the line break on the WYSIWYG surface, where the same caret in a top-level quote (`> a\` over `>··cd`) lands before it. The caret is one place off; the text does not change.
- **A list item that opens with a rule and holds a nested list.** `a`, a blank line, `- ***` and `··- n` load as a raw Markdown block, edited as Markdown text, while the viewer shows a list whose item holds the rule and a nested list. An item that opens with a rule and holds nothing else, or whose rule comes after its text, loads as a rich list.
- **Bold and link in source mode, in some tab-indented list items and quotes.** Where a list item's or a quote's indentation holds tabs, bold and link can do nothing on a word in source mode, and a mode switch can lose the caret's place on some of its lines, in documents where the WYSIWYG command would rewrite more than the word. Indent with spaces, or run the command on the WYSIWYG surface.
- **Undo after a space typed at a line's start.** The editor drops a space typed at a line's start (see *Whitespace at a line's start* under [What Markdown cannot hold](#what-markdown-cannot-hold)). When an input method commits two or more characters, or an emoji, right after such a space, one undo takes the space and the committed text back together, where the same text typed after a letter takes two undo steps. Undo always restores the document; only the number of steps differs.
- **`canInsertTable` and `canInsertHorizontalRule` where the insert does nothing.** For a caret that code sets on a `:::` block right before a table, both fields are `true`, but `insertTable()` and `insertHorizontalRule()` change nothing. A range that code sets over the first rule of `---`, a code block and `---` is the same for `insertHorizontalRule()`, which also moves the caret into the code block. A toolbar control enabled on these fields stays enabled there and does nothing.
- **`insertImage` at a caret that code sets on a table.** With the caret set on a table node or a table row itself, rather than in a cell's text, `insertImage()` inserts nothing and moves the caret into the row or the cell, while `canInsertImage` is `true`. Put the caret in a cell's text first, and the image goes in there.
- **The dirty flag of an editor loaded in source mode before it is shown.** An editor built in `"source"` mode whose document is replaced with `setValue()` before its source editor is first shown reports `isDirty()` `false` after that `setValue()`, and `true` after a switch to WYSIWYG, even when `markClean()` was called in between. Call `markClean()` again after the switch, or pass the document as the `value` option.

### Source-mode colouring

Source mode colours what CodeMirror's Markdown grammar reads (see [CodeEditor's built-in languages](/components/CodeEditor#built-in-languages)). In these cases the grammar reads otherwise than the viewer, so a colour does not match what the viewer shows. The text, the save and the source-mode commands, which read with the viewer's parser, are not affected.

- **A `>` indented four or more columns.** In `> a` over `····>→#→h`, the second line is coloured as a heading in the quote; the viewer reads it as more of the quote's paragraph, `a > # h`.
- **A `:::` line inside a link's text.** `[a` over `::: b](u)` colours the second line as a dialect line, and the brackets and the address are not coloured as a link; the viewer reads one link.
- **A `:::` line right under paragraph text.** It ends the paragraph in source mode, so a code span, an HTML tag or a setext underline that runs across it is not coloured: `` `a `` over `` ::: b` ``, `a <span` over `::: b>`, and `:::` over `===`, which the viewer shows as a heading.
- **A table whose delimiter row starts with `- `.** `a | b` over `- | -` over `c | d` is coloured as a paragraph and a list; the viewer shows a table.
- **A list item that opens with a blank line.** In `9.` over a blank line over `···j`, `j` is coloured as part of the item; the viewer, as CommonMark, ends the empty item at the blank line and reads `j` as a paragraph.
- **A single `-` under a list item's text.** In `- a` over `··-`, the `-` is coloured as an empty nested list; the viewer reads `a` as a level 2 heading in the item.

### Menus

- **Checkmarked menu rows.** The table-cell context menu's **Align column** submenu, and the **Align column**, **Alignment** and **Columns** dropdowns of [`MarkdownDocumentPanel`](/components/MarkdownDocumentPanel), mark the current choice with a check glyph on a plain menu item: the row's role is `menuitem`, with no `aria-checked`, so assistive technology is not told which entry is checked. The format toggles and the **Text style** presets use checkbox and radio rows, which carry `menuitemcheckbox` or `menuitemradio` and `aria-checked`.
