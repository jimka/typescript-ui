# 0.4.0

## Breaking changes

### List

`BulletedList` and `NumberedList` paint their own markers instead
of the browser's, and every item in a marker list now shares one marker
column, as wide as the widest marker, right-aligned inside it. `getStyle()`
still returns exactly what you set, so code keeps compiling — only the
rendered marker and its position change. `UPPER_GREEK` now renders uppercase
Greek (it used to fall back to decimal, not being a predefined CSS counter
style); `LOWER_ALPHA`/`LOWER_LATIN` and `UPPER_ALPHA`/`UPPER_LATIN` render
identically, as CSS defines them; roman numbering falls back to decimal above
item 3999. `AbstractMarkerList` declares a protected abstract
`markerText(index)`; a subclass must implement it (`BulletedList` and
`NumberedList` are unaffected).

### Core

`DOMSource` gains two required members: `startFontLoad(family)`,
returning whether it started an asynchronous font load (the framework treats
`false` as "no activation callback will follow" and skips the startup layout
hold described under *Changed*), and `measureTextWidths(texts, options?)`,
returning one width per input string — the batched form exists so a whole
column-width derivation costs a fixed number of reflows rather than one per
string. Only a consumer implementing its own `DOMSource` is affected.

### Layout

`SplitGutter.destroy()` and `CollapseButton.destroy()` are
removed — both only unhooked listeners and left the component's per-instance
stylesheet rules on the shared sheet. Call the inherited `dispose()` instead,
which does both.

### Table

`Row.syncCells()` is removed, split into `setColumnFields()`
(records the visible fields, per-field configs and tree column) and
`setColumnWindow(firstCol, lastCol)` (builds, recycles and discards cells for
one column range) — a table row now reconciles cells against the body's
current column window rather than the whole visible-field list. A caller that
drove `syncCells` directly calls both in that order, passing `0` and
`fields.length - 1` to render every column as before.

`Row.getComponents()`, `Row.getFieldNames()` and
`TableHeader.getColumns()` now describe only the columns their owner
currently renders, not every visible column. `Row.getColumnWindowStart()` and
`TableHeader.getColumnWindowStart()` convert a position in any of the three
back to a visible-column index by addition. Code indexing one of them by
column number — to reach column `n`, or via `indexOf` — must add the
corresponding offset; code that only iterates is unaffected.
`Table.getColumns()` still enumerates every column.

`Row.getTreeCell()` returns `null` whenever the tree column sits
outside the row's current column window, not only when the row lacks a
`treeFieldName` — a wide `TreeTable` scrolled to the right has no tree cell on
its rows. Callers must null-check on every access rather than caching the
result; the framework's own `TreeBody` call sites already did.

`Body.bindAndPositionRows()` changed signature: the `fallback`
width parameter is dropped in favour of a trailing `columns` argument
describing the rendered column window, and `records` moves ahead of it. A
subclass overriding this protected seam (as `TreeBody` does) must adopt the
new parameter list.

`VirtualRowView`'s protected `onPoolRowAdded()` hook is removed
— the per-pool-slot geometry it let `Body` extend is now keyed on the cell
rather than the slot, so there is nothing left to extend. A subclass that
overrode it should move that work into `createPoolRow`, still called once per
slot added.

`TableHeader.sortColumns()` is removed. It reordered header
cells by `Field.getOrder()`, which the header no longer derives its cell order
from — the column-window reconciler places cells itself, already in the right
order. There is no replacement to call.

A `TableHeader` renders no cells until its first layout pass,
the same way a table body holds no rows until its first render. Code that
constructs a header and reads its cells without laying the table out first
now sees zero columns.

## Changed

### Table

- **A table header and body each render only their horizontally-visible
  columns.** A header cell whose column scrolls out of view is recycled for
  one scrolling in; the group row builds no cells when no visible column
  declares a group (previously one blank cell per ungrouped column). Each
  pooled body row builds cells for the visible range plus a small buffer,
  recycling departing cells for entering columns of the same kind — cell
  count is bounded by the viewport, not the column count. A table narrow
  enough to fit still renders every column. Two consequences follow:
  `Table.setStore()` now ends in a layout pass, like `setColumnVisible`,
  `resetColumns` and `bindView` already did; and `Cell.setBaseBackground()`
  accepts `null` to restore the theme default, since a recycled cell needs to
  lose the previous column's tint.

- **Table columns are now sized and resized by one coherent width model,
  replacing two that used to disagree.** Starting width now comes from a
  per-type policy — `Table.getColumnMinWidth` and `getIntrinsicColumnWidths`
  — replacing the two disagreeing models that used to let a column change
  width the first time it was hidden and shown again; most visible on a
  schema-generated table with no hand-authored widths. Dragging a column
  edge now takes width from more than one neighbour instead of stalling once
  the adjacent column hits its minimum: width comes nearest-first along the
  row, and once nothing is left to take, the table itself widens and scrolls
  instead of stalling, bounded by the columns' own maximums; a leftward drag
  narrows the table back before it regrows any column. The last column's
  right edge is now a working resize handle for the table's own width.

### Cross-cutting

- **The first layout pass now waits for the web font to activate.** Text
  measured before the bundled Manrope face activates used to commit
  fallback-derived sizes and then jump when the real face arrived. The
  coalesced layout queue now holds its first flush until the font set reports
  the load settled (bounded at 50ms, skipped entirely where no asynchronous
  font load started). `Tree` and the table body also defer their own render
  passes during the hold, since both render from synchronous entry points
  rather than the layout queue. Three consequences: `flushLayout()` and
  `resumeLayout()` bypass the hold everywhere except `Tree` and the table
  body, which still check it, so flushing one during startup leaves its rows
  unrendered until the hold ends; a programmatic scroll on either — including
  `Table.selectRecord` — is held the same way; and the post-layout callbacks
  queued during startup (`Component.afterNextLayout`, `Component.onFirstLayout`)
  run after the release rather than on the first frame.

### Display

- **An animating `Canvas` or `WebGLCanvas` now redraws at up to 30fps by
  default**, rather than on every animation frame — previously the same
  canvas cost three times as much on a 180Hz monitor as on 60Hz. Motion
  driven from the new `elapsedMs` argument is unaffected; motion that
  advances a fixed amount per draw call will run slower and should be
  converted to `elapsedMs`. Restore the old behaviour with `maxFps: 0` (or
  `setMaxFps(0)`).

## Added

### Core

- **`Component.getContentBounds()`** — the rectangle a component's children
  are laid out into: the `getContentInsets()` origin plus the
  `getInnerSize()` extent. Place children inside it — from `doLayout` or any
  other method that positions them, such as a row renderer's
  `layoutChildren` — rather than reading `getWidth()`/`getHeight()`, which
  include the border. Returns `null` before the element exists.

- **`Favicon`, `DEFAULT_FAVICON` and `BodyOptions.favicon`** — `Body.init`
  installs a built-in mark by default. Pass `favicon: '/brand.svg'` for your
  own, or `favicon: false` to install none. A `<link rel="icon">` already
  present in the page's HTML always wins.

- **`Util.measureTextWidths(texts, options?)`** — measures many strings in one
  batch, returning one width per input.

### Table

- **`TablePanel(store, spec?)`** — an optional column spec, so a panel-hosted
  table can be configured the same way a bare `Table` can. `TablePanel`
  previously accepted no spec at all, leaving its columns unconfigurable.

- **Automatic column sizing from content** — `ColumnSpec.autoSizeColumns` opts
  a table into sizing its `string` and `auto` columns from the data as well as
  the header. `boolean`, `glyph`, `date`, `time`, `datetime` and `number`
  columns are sized from their type with or without the flag. At most 50
  records are read, and a whole derivation costs at most three batched text
  measurements regardless of column count — derivations run on first layout,
  store swap, reset, and the single post-load re-derive, never per row and
  never on scroll.

- **`ColumnConfig.width` and `ColumnConfig.maxContentLength`** — an explicit
  starting width for a column, and a cap on how much sampled content counts
  toward an automatic one. An explicit `width` outranks every derived value.
  Read them back with `Column.getWidth()` and `Column.getMaxContentLength()`.

- **`Table.isAutoSizeColumns()`, `Table.getColumnMinWidth(column)` and
  `Table.getIntrinsicColumnWidths()`** — the public seam a custom layout can
  read to size columns the way the built-in table layout does.

- **`Table.getAvailableColumnWidth()` and `Table.getColumnWidthTarget()`** —
  the width the columns have to fill, and the total a resize drag has grown
  them to (`0` when the columns still fit without growth).

- **`Row.setColumnFields()`, `Row.setColumnWindow(firstCol, lastCol)` and
  `Row.getColumnWindowStart()`** — the two halves of what `syncCells` used to
  do, plus the offset that converts a position in `getComponents()` /
  `getFieldNames()` back to a visible-column index.

- **`HeaderColumnGeometry`** — the geometry a table layout hands the header on
  each pass: the per-column widths, the width they are windowed against, and
  the two row heights. Exported from `@jimka/typescript-ui/component/table`.

- **`TableHeader.renderColumnWindow(geometry?)`** — reconciles the rendered
  header cells to the horizontally-visible column range and positions them.
  Called with geometry from the table layout, and with none from the scroll
  path, which reuses the cached value.

- **`TableHeader.setScrollX()` / `getScrollX()`, `TableHeader.setFocusedColumn()`
  and `TableHeader.getColumnWindowStart()`** — the header now owns mirroring the
  body's horizontal scroll offset and painting the focused-column indicator,
  both of which have to re-run whenever the column window slides.

- **`HeaderCell.setFieldName()` / `getFieldName()`** — a header cell can be
  re-targeted at another column's field, which is what lets a cell be recycled
  across columns instead of rebuilt.

- **`VirtualScroller.dispose()`** — disposes the scroller's two overlay
  `Scrollbar`s. `VirtualRowView` calls it on teardown, so an owner of a
  `Table`, `TreeTable` or `Tree` needs no change.

### Display

- **`Canvas` and `WebGLCanvas` hand their draw hook the elapsed animation
  time.** `onDraw`/`onFrame` receive a fourth argument, `elapsedMs`: ms since
  the animation run started, or `0` when not animating. Deriving motion from
  it instead of frame count is refresh-rate independent — a per-call counter
  otherwise advances three times faster on a 180Hz monitor than on a 60Hz
  one. Ignoring the argument compiles and behaves exactly as before. Outside
  the animation loop (a resize, a DPR change, an explicit `redraw()`) the
  value repeats the most recent frame's, so a redraw re-renders the same
  moment rather than jumping.

- **`Canvas` and `WebGLCanvas` accept a `maxFps` cap.** New `maxFps` option plus
  `setMaxFps` / `getMaxFps`, bounding how often the animation loop draws. A
  frame arriving sooner than `1000 / maxFps` after the last draw is skipped; the
  loop keeps running, so the cap trades smoothness for CPU rather than pausing
  anything, and changing it takes effect on the next frame. Pass `0` to opt out
  and draw on every frame the browser delivers.

## Fixed

### Table

- **Horizontal table scrolling no longer lays out every cell it scrolls
  past.** A cell's position is content-absolute — scrolling translates rows,
  not cells — so a cell that keeps its column keeps its geometry. Both the
  body's pooled rows and the header now skip a cell whose geometry is
  unchanged, keyed on the cell rather than its position (position-keying
  meant every column-window slide re-laid-out the whole pool). On a
  45-column table 12 columns wide, one column of scroll went from 363 cell
  layouts to none beyond the cells actually entering the window.

- **A glyph cell rebound to a different glyph no longer renders it
  unsized.** The glyph renderer replaces its child component on a value
  change, but the replacement had no bounds until something laid it out —
  which a scroll that rebinds the row doesn't do, since the cell keeps its
  geometry. The renderer now lays itself out when it swaps the child.

- **`HeaderCell.setHeaderGlyph()` now takes effect immediately.** Mounting
  or clearing a header glyph shifts the label's inset, but the setter never
  ran a layout pass to apply it, so the label kept its old indent until some
  other pass happened to re-fit it. The setter now lays itself out, as
  `Cell` already did when swapping its active renderer.

- **A component disposed part-way through a layout flush no longer aborts
  the rest of it.** The flush snapshots its queue once, so a component
  disposed by an earlier entry in the same pass was still laid out — writing
  through an already-released handle, which threw and left everything
  queued behind it unlaid. This covers disposal *during* a flush (disposal
  *between* frames was already handled); table column virtualization
  reaches it on an ordinary path by discarding cells as a side effect of the
  table's own layout. The same guard also skips a component that called
  `scheduleLayout()` before its first render.

### Cross-cutting

- **Bordered components no longer clip their own children.** Eleven
  `doLayout` overrides, plus the tree row's own child placement, placed
  children against the border box instead of the content box, so the last
  child overflowed by the border width and `overflow: hidden` clipped it. On
  a 125% display this showed as a shaved edge on `DateField`, `TimeField`
  and `DateTimeField`'s calendar/clock glyphs, `AutoCompleteField`, and
  `List`/`MultiSelectList` rows. `ComboBox` now also honours its own padding
  when placing its label and caret. `Dialog`'s title bar, `Tooltip` and
  `DragGhost` carry a border under the shipped themes and so change
  slightly: the dialog's close button moves up a pixel, a drag ghost's label
  loses 2px in each dimension, a tooltip's outer box grows 2px in each
  dimension. `MenuItem` and the tree cell renderer are borderless today so
  unaffected, but carried the same defect — `MenuItem` needed a second fix
  before its labels fit (see below).

  A tree row was fixed the same way — reachable only through a `Tree`
  subclass's protected row pool — with one residual: it still reports its
  natural width without its own perimeter, so a bordered row's widest label
  can still clip at full right-scroll.

  The four public row renderers — `LabelTreeNodeRenderer`,
  `IconLabelTreeNodeRenderer`, `LabelListItemRenderer` and
  `GlyphListItemRenderer` — carried the same defect in `layoutChildren` and
  are fixed too; all four are borderless under the shipped themes, so
  nothing changes today, but a consumer bordering one (or writing their own
  `TreeNodeRenderer`/`ListItemRenderer`) should place children inside
  `getContentBounds()` rather than at `(0, 0)` against the outer box.

  A new `local/require-content-bounds` lint rule now catches this class of
  defect across the library — any instance method that places a child
  against an outer or inner box it shouldn't, unless it accounts for the
  border. It found twelve sites: the bordered `MenuItem`, `ProgressBar`,
  `ProgressSpinner`, `Slider`, and the table's footer and header row-sizing
  are fixed below; `VirtualScroller.layoutScrollbars`,
  `ScrollStrip.layoutContent` and `Scrollbar.setMetrics` in the scroll-chrome
  entry further down; `Cell.alignEditorWithContent` in the table-cell entry
  further down still; `TableHeader.setWidth` is deleted outright in the
  header-band entry below (redundant with the table layout manager); one
  site remains baselined, latent because it is borderless today.

  A new **Content Box** demo panel borders the affected components —
  including the tree row and row renderers, reachable no other way — so
  what the rule can't see (a child positioned correctly but sized from a
  stale measurement) stays visible too.

- **A table's footer sizes its inner row to its content box.** It handed
  the row its own full outer extent, though the row already sits inside the
  footer's border. `FooterRow`'s row is now a pixel shorter, matching the
  1px top border every shipped theme gives the footer — not visible today,
  since `Table` has no footer-visibility setter despite what
  `docs/components/Table.md` says. A related defect in the *layout manager*
  — `layout/Table` gave the header band's cells the band's full outer
  height rather than its content height, clipping the last pixel off every
  header cell by default — is fixed in the header-band entry below; the
  lint rule can't see it since it lives in a `LayoutManager`.

- **`ProgressBar`, `ProgressSpinner` and `Slider` honour their own
  padding.** All three sized children correctly from `getInnerSize()` but
  placed them at origin `0` — the inner edge of the border, not the inside
  of the padding — which would have overrun the far edge on a padded
  instance. The origin now comes from `getContentBounds()`. `Slider`'s hit
  test (`valueAtPointer`) needed the same fix, or a padded thumb would trail
  the cursor on every drag. None of the three carries padding under any
  shipped theme, so nothing changes today; the fix only stops biting the
  first consumer who sets some.

- **A `Tree`'s scrollbars, a `ScrollStrip`'s clip and paging arrows, and a
  `Scrollbar`'s thumb and arrow caps now stay inside their owner's content
  box.** `VirtualScroller.layoutScrollbars` positioned both scrollbar
  overlays and the scroll clip against the owner's outer box, so a bordered
  `Tree` or table body ran the far scrollbar edge past the frame into the
  clip. The effective viewport — what every scroll clamp, shadow ramp and
  `Tree` fill-width row uses — moves with the fix, so a bordered owner can
  scroll further because it can see less. `ScrollStrip.layoutContent` and
  its private `layoutArrows` carried the same defect, invisible to the lint
  rule since it places children from delegated arguments.
  `Scrollbar.setMetrics` gained a private `axisBox()` that `getTrackLength`,
  `getTrackOrigin` and the track-click hit test now share, so the thumb,
  arrow caps and click-to-page math all agree on where the track starts and
  ends. None of the three carries a border under any shipped theme, so this
  is pixel-identical today.

- **`Cell.alignEditorWithContent` no longer runs the active cell editor
  past the cell's border, or short of a padded cell's content origin.** It
  read the cell's outer width instead of `getContentBounds()`, so a
  bordered cell's editor overran the clipped far edge, and padding
  additionally left its left edge short of the value it aligns to. No
  shipped theme borders a table cell, so nothing renders differently today.
  New offline tests give `TreeCellRenderer.doLayout` its first coverage of a
  border-and-padding combination, the only configuration the unfixed
  arithmetic got wrong.

- **A table's header band is one pixel taller: it now adds its own bottom
  border to the height its rows need**, instead of splitting the band's
  outer height between them and letting `overflow: hidden` clip the last
  pixel off every header cell. `layout/Table.doLayout` gave the band
  exactly the height its two rows needed, then split that height between
  them — but the rows' containing block was one pixel shorter than the band
  because of its own bottom border, so the header's `overflow: hidden`
  silently clipped the last pixel off every cell, today, by default. The
  band now grows by the header's own perimeter instead, and rows and the
  scrollbar cover are placed from `header.getContentBounds()`. Nothing
  moves under the shipped themes except by the band's extra pixel: the
  divider, body origin and every body row shift down one. `TableHeader.setWidth`
  is gone — it forwarded a width the layout manager immediately overwrote.
  The footer band is corrected the same way, though it cannot be switched
  on today. This is a manager reaching into a child's subtree, which
  `local/require-content-bounds` can't see; the fix is guarded by new
  offline tests instead.

- **Size hints that depend on a border are re-derived when it changes.** A
  `TextField` cached its one-line box at construction, so a border added or
  removed at runtime kept the old height. Consequences: a `NumberSpinner`'s
  minimum height drops 26 to 24 (master shipped it above its own maximum,
  2px taller than every other form-row field), and the string/number cell
  editors' inner fields report their true borderless height. Setting a
  border now rewrites preferred/minimum height and a *bounded* maximum,
  leaving an unbounded maximum alone.

- **A `MenuItem`'s labels are pinned to the item's content height, not its
  outer height.** Each of the four labels (icon, title, shortcut, chevron)
  was centred against `MenuItem.HEIGHT` — the fixed 24px *outer* height —
  which also pinned their minimum, so a bordered item's smaller content box
  couldn't shrink them. Labels now re-pin to the content height at
  construction and on every `setBorder`/`clearBorder`. No shipped theme
  borders a `MenuItem`, so this is visible only in the Content Box demo
  panel or for a consumer who borders one.

- **`setWillChange` survives the first render.** `applyStyle` clears the
  element's inline style and replays cached style fields, but no phase
  replayed `will-change` — so a hint set before the element rendered was
  silently dropped, including every hint supplied through the options bag.
  `getWillChange()` kept reporting the cached value, so the loss was
  invisible except in the browser. It now replays alongside `transition` and
  `opacity`.

- **Component constructors accept a `subclassDefaults` bag.** Twenty-nine
  constructors passed their own `_defaultXxxOptions` constant straight to
  `super()`, a dead end that left editing the parent's own constant as the
  only way to seed a class default. Each now takes an optional
  `subclassDefaults` parameter layered over that constant, matching
  `Component`, `ComboBox` and `TextInput`. It's optional and spread last, so
  existing construction is unaffected and a caller-supplied option still
  wins. A new `local/require-subclass-defaults` lint rule guards the
  pattern.

- **Several components no longer leak stylesheet rules on teardown.** Each
  had appended a DOM child straight onto its owner's element instead of
  registering it as a child component, so the owner's recursive
  `destructor()` never reached it — the same root defect the removed
  `SplitGutter.destroy()`/`CollapseButton.destroy()` had (see *Breaking
  changes*); `dispose()` is the one path that now always reaches it. A table
  header's `HeaderCell` mounted a resize handle, sort-priority badge and
  header glyph this way: roughly 102 rules per open/close cycle of the
  45-column demo table, now 0 after three cycles, and swapping a glyph now
  disposes the outgoing one too. A table/tree/tree-table's virtual row pool
  appended pooled rows (and their cells) the same way, growing the sheet by
  roughly the view's whole cell count per teardown — measured on a
  45-column table, one open-and-close cycle now retains 104 rules where it
  used to retain 5512. Overlay scrollbars, split/border/accordion gutters,
  accordion section headers and wrappers, a `Rail`'s collapse chevron, and a
  dock region's drop-zone overlay carried the same defect and are fixed the
  same way. `DragManager` built a `DragGhost`, `DragFeedback` and
  `ReorderIndicator` per committed drag and only detached them, so the sheet
  grew by one rule per drag and never shrank; a caller-supplied
  `ghostFactory` ghost is still only detached, since it belongs to the
  caller.

### Display

- **Animated glyphs no longer cost main-thread work on every frame.** A
  `Glyph`'s root was an `<svg>`, and browsers won't run a `transform`
  animation on SVG on the compositor thread — every animated glyph forced a
  main-thread layer rebuild each frame, at a cost that scaled with the whole
  page: measured at 3.66ms/frame (~21% of a CPU core) with a 45-column table
  open elsewhere. An SVG glyph now renders as
  `<span><svg><use/></svg></span>` with the animation class on the
  compositing `<span>`; consumers who append `glyph.getElement()` directly
  now get that `<span>` instead. `setAnimated` no longer sets `will-change:
  transform` — glyphs are numerous enough that hinting each one would exceed
  the count browsers honor. Two related defects are also fixed: a
  construction-time duration was wiped before first paint, and
  `animationDuration` without `animation` wrote an orphan duration onto a
  glyph that never animated.

- **An animated `Glyph` now pauses while it is off-screen.** A glyph
  animated via `setAnimated` (or the `animation` option) kept running for
  the lifetime of the page even once no longer effectively visible — a
  hidden tab, a collapsed section, any hidden ancestor — costing a
  compositor frame every refresh. `ProgressSpinner`/`ProgressBar` were
  unaffected, since they animate through `Component.setAnimation`, which the
  effective-visibility pass already paused; `Glyph` drives its animation
  from a shared class rule the pass couldn't see. Glyphs now pause and
  resume with effective visibility like every other animated component,
  most noticeable on high-refresh monitors and large component trees.

### Layout

- **A wrapped `HFlow` or `VFlow` no longer under-reports its size.** Both
  reported their single-line shape regardless of how many rows their
  children actually wrapped into, so a parent honouring preferred sizes
  sized the host for one line and clipped the rest. Each flow now reports
  the cross extent measured at its last layout; the main axis is unchanged
  (still the full unwrapped aspiration). The cross-axis maximum is floored
  at that measurement; the minimum stays one line's worth, now measured
  with the same `itemAlign` rule the preferred size uses. A layout with
  nothing usable to measure (unresolved child, or host with no width yet)
  keeps reporting the single-line estimate.

- **Wrapped `HFlow` rows no longer overlap under `itemAlign: "baseline"`.**
  A row advanced by its tallest cell, but baseline alignment can push a
  low-baseline child's descender (`rowAscent - baseline`) below that, so the
  next row started underneath it. A baseline-aligned row is now as tall as
  `rowAscent + rowDescent`. This changes rendered output only for wrapping
  flows using `itemAlign: "baseline"`; `VFlow`'s baseline arm still degrades
  to `"start"`.

- **`Border.doLayout()` and `Accordion.doLayout()` no longer fail when they
  run before the container has a DOM element.** Both now defer to the next
  pass, matching `HBox`, `VBox`, `Grid`, `Split` and `Tab`. An `autoScroll`
  host's synchronous layout pass during its own construction used to
  trigger this against a not-yet-rendered child.

- **`VBox`, `HBox`, and the flow layouts no longer let a child's smaller
  maximum win over its explicit larger minimum.** `resolveChildHeight`,
  `resolveChildWidth` and `clampedPreferredSize` capped to the maximum and
  then floored to the minimum — backwards from every other clamp in the
  framework — so a component with a hard maximum (`ComboBox` capping its
  own height, for instance) could shrink an ancestor's reserved cell below
  its explicit minimum, and the next sibling advanced into the space never
  given back. All three now cap to the maximum first and floor to the
  minimum last, matching `clampPreferredToConstraints` and `clampWidth`.
