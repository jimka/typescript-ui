# 0.4.1

## Breaking changes

### Layout

Closing a tab now disposes its content component. `Tab` (and
therefore `TabPanel` and `Dock`) treats a close as a destroy — the content,
its children, and everything their `destructor()` overrides reach are torn
down and their per-instance stylesheet rules released. A caller that holds a
closed tab's component to re-add later must pass the new
`LayoutConstraints.disposeOnClose: false` (or `DockPanelSpec.disposeOnClose:
false`, or `TabPanel.addTab`'s `disposeOnClose: false`). A `"tabclose"`
listener that re-parents the content also keeps it. Tear-off and re-dock are
unaffected.

## Added

### Layout

- **`LayoutConstraints.disposeOnClose`, `DockPanelSpec.disposeOnClose`, and a
  `disposeOnClose` option on `TabPanel.addTab` / `addLazyTab` / the `tabs`
  config entries** — the opt-out from the breaking change above, for a
  component the caller owns and intends to re-use after its tab closes.
- **`PanelNode.tooltip` / `.closeable` / `.disposeOnClose`** on the serialized
  layout leaf, alongside the existing `glyph` — a restored tab now keeps its
  presentation and close-behaviour constraints.

## Fixed

### Core

- **Disposing a component now unregisters its DOM listeners.** Previously
  every disposed component left its entries in the `Event` module's
  registration maps, which hold the component itself — so the instance and
  everything its handlers captured were retained for the life of the page, a
  component disposed with a live viewport listener kept handling `resize` /
  `keydown` events, and the garbage-collection backstop that releases a
  discarded component's handles and stylesheet rules could never run for it.
  No consumer action is needed.

### Layout

- **A closed tab no longer strands its content's — or its own strip button's
  — stylesheet rules on the shared sheet.** Closing one 20-column, 42-row
  table tab used to leak 2288 rules per open/close cycle, without bound. A
  restored layout now also keeps each tab's `closeable`, `tooltip` and
  `disposeOnClose`, which `serializeLayout` previously dropped (only the
  glyph survived), so a restored tab no longer silently loses its ✕.

### Overlay

- **A dismissed `Notification` is now disposed rather than only removed from
  the DOM**, releasing its own and its close button's stylesheet rules and
  unhooking its two subtree listeners.
- **A `Menu` opened at least once and then disposed no longer strands its own,
  or an open submenu's, stylesheet rules.** `Menu` is never a registered
  child of the component that opens it, so `MenuButton`, `SplitButton`,
  `ToolBar` (its overflow dropdown), `Table` (its column context menu),
  `MenuBar` (each top-level dropdown), and `TabBar` (its own right-click
  context menu) now dispose their `Menu` explicitly on teardown, and `Menu`
  itself now disposes a still-open child submenu and unregisters from the
  layer tree on `dispose()`. This is the residual leak left behind after the
  tab-content fix above: it accounted for most of the ~78 rules a closed
  20-column table tab still leaked per cycle once that fix landed. No
  consumer action is needed.
